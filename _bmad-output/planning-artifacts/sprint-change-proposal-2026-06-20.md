## Раздел 1. Сводка проблемы (Issue Summary)

**Что произошло.** Story 0.1 устанавливает официальный канал доступа (`GOSZAKUP_TOKEN` →
ows_v2). Получение токена — действие человека через профиль участника goszakup.gov.kz; токен
пока не получен. Это блокирует живую верификацию (AC2/AC3/AC4) и, по плану, Epic 2 (импорт) и
Epic 3 (гео).

**Решение владельца (осознанное).** Временно использовать **парсер публичного портала**
(`stage0-audit/scrape.go`, `-source scrape`) как **основной источник данных**, пока токен не
получен; токен подключить позже. Принято после явного показа конфликта с несущим принципом
(дважды) и эмпирических ограничений.

**Категория:** стратегический пивот (временный), вынужденный внешней предпосылкой (нет токена).

### Доказательная база (evidence)

1. **`.gitignore` уже защищает `.env`**, токена нет в окружении (проверено).
2. **Парсер lots-only** — разовый прогон `-source scrape -sample 30` (2026-06-19): доступны
   только лоты (поля `amount, name_ru, ref_kato, trd_buy_number_anno`);
   `contract/trd-buy/rnu/acts/subject/journal` → «недоступен без авторизации (нужен токен)».
3. **Выборка keyword-смещена** — `scrape.go:129` ищет по словам направлений → доля направлений
   (AC4) на такой выборке не показательна (циркулярность).
4. **Конфликт с архитектурой/правом:**
   - §6.1: «официальный канал, а не обходной парсинг — принципиально для юридической чистоты».
   - architecture.md:94–96, 275–276, 395: «скрейпинг невозможен по структуре» (`scrape.go` в
     `tools/`, build-tag, вне продового бинаря).
5. **Существует лучший токен-независимый путь** — epics.md:562–563: Epic 1 (walking skeleton)
   «не зависит от живого API и гейта №0 (синтетика / ручные evidence)»; architecture.md:911–918:
   S-0 строится на синтетике **параллельно** гейту №0.

> Владельцу показано, что **синтетика (Epic 1) даёт больше, чем парсер, без юр-долга** (контракты,
> 4 флага на ручных evidence, ноль §6.1/§6.4-риска). Владелец выбрал парсер. Предложение оформляет
> это решение максимально чисто и обратимо.

## Раздел 3. Рекомендованный путь (Recommended Approach)

**Выбрано: Гибрид (Direct Adjustment + MVP Review) с задокументированным временным
арх-отклонением.**

- **Direct Adjustment:** добавить тонкий **временный** трек «Парсер-мост» новыми историями
  (Epic 0, истории 0.6–0.9), не ломая существующую структуру эпиков.
- **MVP Review:** промежуточный scope = «карта лотов Астаны + направления (предв.) + КАТО-агрегаты».
  Полный MVP (карточки, флаги, медианы) **отодвинут до токена**, не урезан.
- **Параллельно:** Epic 1 (walking skeleton на синтетике) идёт своим чередом — не ждёт токен.

**Почему гибрид, а не «парсер вместо API» (path C):** path C невозможен — без договоров не
строится центральный объект `contracts` и 3/4 флага; нарушает §6.1/§6.4; структурно запрещён.
Гибрид даёт владельцу движение сейчас, сохраняя обратимость и путь восстановления принципа.

- **Effort:** Medium. **Risk:** Medium-High (юридический — активный парсинг). **Timeline:** трек
  параллелен Epic 1; критический путь к полному MVP по-прежнему упирается в токен.

### Путь восстановления (обязателен в proposal)

При получении токена: (1) `Source` scrape→ows одним флагом; (2) выключить `ASHYQQALA_INTERIM_SCRAPE`,
удалить интерим-команду по критерию удаления; (3) восстановить структурный запрет §6.1/§6.4;
(4) прогнать гейт №0 (Epic 0) как задумано; (5) Epic 2 живой импорт замещает scraped-лоты.

## Раздел 6. Открытые риски (явно)

1. **Юридический (активный сейчас):** парсинг противоречит §6.1/§6.4 — «принципиально для
   юридической чистоты». Митигировано временностью + путём восстановления, НО риск реален пока
   токена нет. Владелец принял осознанно.
2. **Throwaway-поверхность:** интерим-команда + флаг удаляются при токене (downstream — нет).
3. **Тонкий scope:** на парсере нет карточек/флагов/медиан — демо «карта лотов», не полный продукт.
4. **Keyword-bias:** направления на scraped-выборке непоказательны (метить «предв.»).
