# Spine Pair Review — AshyqQala.kz

> Reviewer: rubric walker. Read-only validation of the spine pair `DESIGN.md` + `EXPERIENCE.md`
> as a downstream contract (architecture, story-dev). No files were changed.

## Overall verdict

Сильная, добротно собранная пара спайнов: токены полностью резолвятся (0 битых ссылок,
светлая+тёмная пары везде, контраст указан для всех несущих сочетаний), компоненты покрыты
с двух сторон, гардрейлы нейтральности/честности проведены последовательно через оба файла,
три именованных Key Flow с кульминациями и путями отказа. Потребитель может извлечь данные
чисто. Что мешает «strong» по всем осям — несколько незакрытых несущих решений по методике
флагов (порог монополии и carve-out единственного участника схлопнуты в один `<5`; окно
медианы вообще не зафиксировано) и формальные дыры наследования (нет `sources:` во
фронтматтере EXPERIENCE.md; форма ошибки и страница района без собственных состояний). Все
находки — medium и ниже; критичных и high нет.

## 1. Flow coverage — adequate

Извлечены роли из журнала (Гражданин/Айгуль, Подписчик/Ержан, Журналист/Данияр, внутренние
операторы) и требования (UC-01…UC-11, FR-флаги). Три Key Flow покрывают первых трёх
протагонистов: каждый с именованным героем, нумерованными шагами, явной кульминацией и путём
отказа (Айгуль: негеокод+медленная сеть; Ержан: всплеск→дайджест; Данияр: выборка <5). UC-01…07
прослеживаются во Flow 1/3, UC-06 во Flow 2.

### Findings
- **[low]** Четвёртая роль из журнала — «внутренние операторы» (Directus: геопривязка
  UC-09/UC-10, нормализация) — не имеет Key Flow (`.decision-log.md:31`; EXPERIENCE.md Key
  Flows 347–395). Омиссия защитима: Directus явно описан как непубличная админка («гражданин
  её не видит», EXPERIENCE.md:32–33, 73), а спайн — про гражданский опыт. *Fix:* одна строка в
  начале Key Flows, что операторский поток сознательно вне спайна (Directus = внутренний
  инструмент), чтобы омиссия читалась как решение, а не пропуск.

## 4. State coverage — adequate

Пройдены все 12 IA-поверхностей. Несущая «дисциплина честности» покрыта образцово: четыре
состояния данных + cold-load/скелетоны, пустой фильтр, тайлы недоступны, гео <70%, источник
недоступен (локальная копия), РНУ с авто-снятием, «профиль уточняется», фокус-ринг
(EXPERIENCE.md State Patterns 188–209). Карта-режимы и поведение флагов вынесены в отдельные
секции.

### Findings
- **[medium]** Поверхность «Форма «сообщить об ошибке»» (IA: EXPERIENCE.md:70) не имеет
  состояний нигде — нет empty/в процессе отправки/успех/ошибка/валидация. Downstream story-dev
  не сможет извлечь поведение формы. *Fix:* добавить строку в State Patterns или мини-блок
  поведения формы (поля, успех/ошибка отправки, попадание в Directus-очередь).
- **[low]** «Страница района» (IA:66) фигурирует в состояниях только через гео <70% фолбэк
  (205) и упоминается во Flow 3; собственных cold-load/empty (район без объектов) состояний нет.
  *Fix:* строка состояния для пустого/загружающегося района.
- **[low]** «Объяснение методики флага» (IA:68) — нет состояния «evidence/выборки недостаточно
  для показа формулы» как поверхности (есть общий <5, но не привязан к этой поверхности).
  *Fix:* при необходимости — уточнить, что методика показывает формулу даже когда сигнал не
  выставлен.

## 6. Bloat & overspecification — strong

Пиксели появляются только там, где токенов не хватает (тени `0 2px 8px rgba…`,
`stroke-dasharray '5 6'`, форма капли маркера) — это законная визуальная спецификация, не
переспек. Пересказа источника нет: персоны/FR/scope не дублируются, а ссылаются (NFR-1, NFR-6,
NFR-7, runbook ≥5, геогейт ≥70%). Проза DESIGN.md несёт редакторский голос (это допустимо);
проза EXPERIENCE.md — поведенческая, без редакторского голоса. Таблицы используются там, где
проза была бы хуже (IA, микрокопия, состояния, компоненты).

### Findings
- **[low]** Семейство токенов `confirmed*` (6 токенов: `confirmed`, `confirmed-text`,
  `confirmed-soft` ×2 темы) определено и описано прозой (DESIGN.md:37–39, 67–69, 316–320), но
  **не используется** ни одним компонентом и ни одним состоянием EXPERIENCE.md — нет
  поверхности «подтверждено / из первоисточника», которая бы его потребляла. Либо мёртвый
  токен (bloat), либо отсутствующее состояние «подтверждённости» в EXPERIENCE.md (coverage).
  *Fix:* либо привязать `confirmed` к конкретному UI (метка «данные из первоисточника» рядом с
  {source-link}) и дать ему строку в обоих спайнах, либо убрать токены до момента появления
  потребителя.

## 7. Inheritance discipline — adequate

UJ/имена ролей дословны из журнала (Айгуль/Ержан/Данияр); глоссарий гардрейлов идентичен между
спайнами и источниками («сигнал, требующий проверки», «нет данных», «недостаточно сопоставимых
данных»); имена компонентов идентичны во всех секциях обоих файлов; ссылки-токены EXPERIENCE.md
резолвятся в токены DESIGN.md по имени (проверено). Конфликт с NFR-6 (KZ-дефолт vs RU-интерфейс)
честно зафиксирован как осознанное переопределение с проброшенной зависимостью для
архитектуры/данных (EXPERIENCE.md:39–50; журнал 81–89; NFR-6 подтверждён в PRD:305) — это
образцовая дисциплина наследования конфликта.

### Findings
- **[medium]** Фронтматтер EXPERIENCE.md не содержит поля `sources:` (EXPERIENCE.md:1–9 — есть
  только `references: DESIGN.md` и `project:`). Пример-шейп (`experience-example-mobile.md`,
  `-shadcn.md`) и проверка наследования рубрики требуют `sources:` со списком артефактов. Список
  источников живёт в `.decision-log.md`, но downstream-потребитель читает спайн, а не журнал, и
  не сможет резолвить источники из самого файла. *Fix:* добавить `sources:` во фронтматтер
  EXPERIENCE.md (PRD, addendum, use cases v4, data-model-and-flags, конкурсный документ, runbook
  — пути из `.decision-log.md:16–23`).
- **[medium]** Методика флагов в EXPERIENCE.md схлопывает три разных порога источника в один
  `<5`. Data-model различает `median.min_sample = 5` (медиана/флаг цены) и
  `flag.monopoly.min_group_contracts = 5` (монополия) — это разные группы сопоставимости
  (`kato × direction` для монополии vs `direction × kato × период` для медианы), а спайн
  говорит просто «выборка <5» для обоих (EXPERIENCE.md:195, 288, 392). Совпадение значений
  сегодня скрывает, что это две настройки. *Fix:* в «Поведение риск-флагов» развести пороги по
  флагам (медиана/цена и монополия — отдельные `min_sample`/`min_group_contracts`).
- **[medium]** Не унаследован carve-out `flag.single_participant.exclude_methods`
  (data-model:75): единственный участник **не** сигналится для способов закупки, где он законен.
  Спайн флагует «единственного участника» безусловно (EXPERIENCE.md:135, 283, Flow 1 шаг 5).
  Downstream выставит ложные флаги на легитимных способах. *Fix:* добавить в «Поведение
  риск-флагов» строку про исключаемые способы закупки.
- **[medium]** Окно медианы не зафиксировано в спайне. Data-model задаёт
  `median.comparability_key = direction × kato × период(24 мес, скользящее)`
  (data-model:76, 84). EXPERIENCE.md говорит лишь «медиана района ×1.5» (283, Flow 3) и не
  называет ни окно (24 мес скользящее), ни ключ сопоставимости. Фильтр «период = 12 месяцев»
  во Flow 3 (380) — это UI-фасет поиска, не окно медианы, но соседство может ввести в
  заблуждение. *Fix:* в «Поведение риск-флагов» зафиксировать окно 24 мес (скользящее) и ключ
  сопоставимости медианы; явно отделить от UI-фильтра периода.
