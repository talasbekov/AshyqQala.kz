# EXPERIENCE.md — AshyqQala.kz

Спайн опыта платформы: информационная архитектура, поведение компонентов, состояния
данных, доступность и ключевые сценарии. Визуальная идентичность — в `DESIGN.md`;
здесь — то, как платформа **ведёт себя**. Ссылки на визуальные токены даны синтаксисом
`{token-name}` (например {signal-attention}, {contract-card}, {tap-target}).

## Foundation

**Form-factor — mobile-first веб.** Основная поверхность — адаптивный веб на React + Vite
+ MapLibre GL. **Нативного приложения нет** (Non-Goal). Раскладка — одна колонка, карта
занимает основную высоту, карточка приходит нижним листом {preview-sheet} (см. Layout в
`DESIGN.md`). Цель — гражданин Айгуль на телефоне, на мобильном интернете, на улице, за
~10 секунд.

**Отдельные поверхности.**
- **Telegram-бот** — самостоятельная поверхность (подписка на район, пуш о новом
  контракте/флаге, смена/отписка, антифлуд-дайджест). Не часть веб-SPA.
- **Directus** — внутренняя админка операторов (очереди геопривязки и нормализации). Не
  публичный продукт; гражданин её не видит.

**UI-системы стороннего вендора нет.** Интерфейс кастомный — нет shadcn/Material/иного
импорта. Вся визуальная идентичность (цвет, типографика, формы, компоненты) задана в
`DESIGN.md` (палитра «Открытый город / Баланс», {primary} голубой + {accent} золото,
светлая и тёмная темы). Этот спайн описывает поведение тех же компонентов.

**Язык интерфейса — КАЗАХСКИЙ по умолчанию, переключатель на русский.** Это решение Bratan,
которое **переопределяет NFR-6** (PRD задавал RU-интерфейс с KZ-каркасом на потом). KZ —
дефолт, RU — альтернатива; выбор языка запоминается между сессиями (см. Voice and Tone и
{lang-switch}). Типографика `DESIGN.md` обязана покрывать расширенную казахскую кириллицу
(ә ғ қ ң ө ұ ү і) — это закрыто выбором шрифта Inter + системный стек.

> **Предусловие/риск (из журнала решений, не переспрашивать — зафиксировано как зависимость
> для архитектуры/данных):** доменные данные goszakup часто на русском. Казахский UI требует
> заполненных KZ-полей (`*_kk`: `name_kk`, `subject_kk` и т.п.) **с первого дня**, иначе
> казахский интерфейс покажет на доменном контенте честную пустоту «нет данных» / «деректер
> жоқ». Нужна стратегия KZ-контента (перевод наименований и предметов). Влияет на объём MVP
> и SM-метрики; поднять на этапе архитектуры/PRD-correct-course.

**Темы.** Светлая + ручной переключатель тёмной — в scope MVP. UI-контрол — {theme-switch}.

| **Telegram-бот** | Внешний вход (Telegram) | Подписка/смена/отписка района; пуш и антифлуд-дайджест. Мок: [`mockups/key-telegram-bot.html`](mockups/key-telegram-bot.html) |

### Граф навигации (связи)

```

                         │   КАРТА АСТАНЫ    │ (cold start)
                         └────────┬─────────┘
                       тап маркера │ ↑ закрыть лист
                                   ▼
                         ┌──────────────────┐        поиск/фильтры
                         │  ПРЕВЬЮ ОБЪЕКТА   │◄──────────────────────┐
                         │ (нижний лист)     │                       │
                         └────────┬─────────┘                ┌───────┴────────┐
                      «Подробнее» │                          │ ПОИСК + СПИСОК  │
                                   ▼                          └───────┬────────┘
            ┌─────────────────────────────────────┐                  │
            │        КАРТОЧКА КОНТРАКТА            │◄─────────────────┘
            │  (флаги · сумма · метаданные)       │
            └──┬─────────┬──────────┬─────────┬───┘
     поле     │  поле    │  бейдж   │  ссылка │  «сообщить
  «Подрядчик» │ «Район»  │  флага   │ первоист.│  об ошибке»
              ▼          ▼          ▼         ▼          ▼
    ┌──────────────┐ ┌────────┐ ┌─────────┐ ┌────────┐ ┌──────────┐
    │  ПОДРЯДЧИК    │ │ РАЙОН  │ │МЕТОДИКА │ │goszakup│ │ ФОРМА    │
    │(РНУ·преобл.)  │ │(медиана│ │ ФЛАГА   │ │.gov.kz │ │ ОБ ОШИБКЕ│
    └──────┬───────┘ │ ·список)│└─────────┘ │  ↗ внеш.│ └──────────┘
   контракты│        └───┬────┘             └────────┘
            └────────────┘ (взаимные ссылки контракт ↔ подрядчик ↔ район)

  ОТДЕЛЬНО:  Telegram-бот ──(deep-link)──► страница района / карточка контракта / ФОРМА ОБ ОШИБКЕ
             Directus ──(операторские очереди, публике не видны)──► данные
             OG-превью ──(серверный рендер при шаринге)──► карточка контракта (+ методика, +первоисточник)
```

**Несущие связи навигации:** контракт ↔ подрядчик ↔ район ↔ флаг (взаимны и
двунаправлены); карта ↔ карточка (через превью-лист). Из любой поверхности с флагом тап
по {flag-badge} ведёт в объяснение методики. Ссылка-первоисточник {source-link} всегда
уводит наружу в goszakup. Модальные слои стекаются максимум на один уровень (лист превью
ИЛИ объяснение методики, не оба сразу).

**Правило достижимости защитных связей (юр-гардрейл §7.1/FR-28, FR-23).** Везде, где флаг
**доходит до третьих лиц** — карточка контракта и подрядчика, превью-лист, OG-превью при
шаринге, Telegram-пуш/дайджест — рядом с флагом обязаны быть доступны (а) путь к
объяснению методики/пересчёту и (б) канал «Сообщить об ошибке». На интерактивных
поверхностях это интерактивные ссылки; на неинтерактивных (OG-картинка, текст пуша) — это
ссылки в подписи/тексте на методику, на первоисточник goszakup и на форму об ошибке. Флаг
без сопровождающего пути к методике и каналу возражения **не публикуется** ни на одной
поверхности.

→ Композиционные референсы (визуальная проба, не источник истины):
[`mockups/directions-1.html`](mockups/directions-1.html), [`mockups/color-themes-1.html`](mockups/color-themes-1.html). При конфликте спайны побеждают любой мок.

## Voice and Tone

Микрокопия. Тон бренда и эстетика — в `DESIGN.md`. Несущий гардрейл повторяется здесь как
поведенческое правило: **каждый риск-флаг — «сигнал, требующий проверки»**, никогда —
«нарушение / коррупция / виновен». Честность важнее вывода: отсутствие данных показывается
как «нет данных», недостаток выборки — как «недостаточно сопоставимых данных», без домыслов.

**Поведенческие правила тона:**
- Нейтрально и неканцелярски; показывать как объекты с сигналами к проверке, так и добросовестных.
- Без тревоги, обличения и оппозиционности.
- Лексикон «нарушители / разоблачаем» запрещён в UI, OG, пушах, лендинге и маркетинге — он
  окрашивает нейтральный сигнал в обвинение (полный список запретов — ниже).

> **Предусловие KZ-нейтральности (зависимость, не переспрашивать).** Казахский — язык
> по умолчанию, то есть юридически первичная витрина. **Все** казахские формулировки в
> этом документе (микрокопия флагов, честных состояний, бот, OG) — **черновик-каркас и
> требуют валидации носителем-юристом до релиза**. Помеченные ниже строки (например
> KZ-имя флага преобладания) подтверждаются носителем явно. RU- и KZ-копирайтер
> одинаково связаны списком запретов в обоих языках (см. ниже).

**Запреты микрокопии (поведенческие) — в ОБОИХ языках:** запрещены везде (UI, OG-превью,
пуши бота, лендинг, пресс-релиз):
- **RU:** «нарушение», «коррупция», «виновен», «преступник», «вор», «нарушитель», «разоблачаем», «схема».
- **KZ:** «бұзушылық» (нарушение), «сыбайлас жемқорлық» (коррупция), «кінәлі» (виновен),
  «қылмыскер» (преступник), «ұры» (вор), «әшкерелейміз» (разоблачаем).

Восклицательные «разоблачения», тревожный тон, призывы к действию против лица — запрещены.
Слово «недобросовестный» / «жосықсыз» допустимо **только** как часть официального названия
государственного реестра (РНУ) со ссылкой и атрибуцией государству, **никогда** как
характеристика подрядчика от платформы. Пустота никогда не маскируется нулём,
прочерком-«0 ₸» или выдуманным значением.

| Делать | Не делать |
|---|---|
| «… — сигнал, требующий проверки» / «тексеруді талап ететін сигнал» | «Нарушение / бұзушылық», «коррупционная схема», «виновен / кінәлі» |
| «нет данных» / «деректер жоқ» | «0 ₸», «—», «н/д» как маскировка отсутствия |
| «недостаточно сопоставимых данных» / «салыстыруға жеткілікті дерек жоқ» | Показывать медиану/флаг при выборке ниже порога |
| «делает работу власти видимой» / «билік жұмысын көрінетін етеді» | «разоблачаем чиновников / әшкерелейміз», «нарушители / бұзушылар» |
| «Есть запись в гос. реестре (РНУ)» с атрибуцией государству | Называть подрядчика «недобросовестным / жосықсыз» от лица платформы |

## Component Patterns

Поведенческие правила. Визуальные спецификации — в `DESIGN.md.Components`.

| Компонент | Поверхность | Поведение |
|---|---|---|
| **Карточка контракта** {contract-card} | Превью · полная карточка · список | Над-метка label-caps («КЕЛІСІМШАРТ · ЖОЛ»). Сумма {amount} — самый весомый элемент. Поля «Подрядчик» и «Район» — кликабельные ссылки (переход на соответствующие карточки). Любое отсутствующее поле рендерится честным состоянием {data-state-nodata}, не прячется. В превью — компактная версия; «Подробнее» раскрывает полную. Мок: [`mockups/key-contract-card.html`](mockups/key-contract-card.html). |
| **Карточка подрядчика** {contract-card} | Из контракта · поиск | Агрегирует репутационные метки по БИН. У **каждой** метки (запись РНУ, преобладание в районе, цена/км) — **своя** {source-link} на свой первоисточник (реестр РНУ ↗, перечень контрактов) и **локальная** ссылка «Сообщить об ошибке» рядом с меткой, не одна общая. Флаги **не строятся** на неполных/неразрешённых данных: пока нормализация в статусе manual/conflict — показываем «Профиль уточняется» и оговорку «профиль подрядчика ещё дополняется» рядом с любым уже показанным флагом. Мок: [`mockups/key-contractor-card.html`](mockups/key-contractor-card.html). |
| **Бейдж флага** {flag-badge} | Карточка контракта/подрядчика, превью, список | Пилюля на мягком амбер-фоне с амбер-точкой и **глифом «!»** (не-цветовой признак, паритет с {map-marker-flagged}). Текст всегда «… — сигнал, требующий проверки». **Тап по бейджу → объяснение методики флага** (формула, evidence, methodology_version, дата расчёта, кнопка «пересчитать вручную»). Рядом с бейджем — «Сообщить об ошибке». Бейдж — интерактивная цель ≥ {tap-target}, role=button, aria-label с полной формулировкой, видимый {focus-ring}. Никогда не алый. Мок методики: [`mockups/key-flag-methodology.html`](mockups/key-flag-methodology.html). |
| **Маркер обычный** {map-marker-point} | Карта | Каплевидный голубой {primary} пин **без глифа** (пустой пин — первичный не-цветовой признак «обычный»). Тап → превью-лист {preview-sheet}, маркер переходит в {map-marker-selected}. Хитбокс ≥ {tap-target} даже при мелком пине; видимый {focus-ring} при фокусе. |
| **Маркер с флагом** {map-marker-flagged} | Карта | Пин с **глифом «!»** (тот же «!», что в {flag-badge}) — статус «есть флаг» несёт прежде всего форма/глиф, амбер {signal-attention} — **вторичный** признак. Визуальная весомость **равна** голубому: амбер-пин не «громче» и не «горячая точка» (см. Inspiration & Anti-patterns). z-priority выше обычного при перекрытии (см. деконфликт ниже). |
| **Маркер подтверждён** {map-marker-confirmed} | Карта | Пин с **глифом «✓»** (сине-зелёный {confirmed}) — «данные из первоисточника». Не «зелёный светофор». |
| **Маркер выбран** {map-marker-selected} | Карта | Любой статус при выборе: увеличенный ×1.25 пин с **двойным кольцом-обводкой** (форма — не-цветовой признак выбора), сохраняет глиф своего статуса (!/✓/пусто); золото {accent} — вторично. Высший z-priority (выбранный > флаг > обычный). |
| **Линия** {map-line} | Карта | Полилиния дороги/трубопровода (голубая с casing и пунктиром). Тап в пределах hit-tolerance ≈ {tap-target}/2 от оси линии = выбор объекта → превью. **Выбранная** линия — золотой stroke {map-line.stroke-selected} + casing {map-line.casing-selected} (паритет с выбранным маркером). Превью линии несёт линие-специфичные поля: `length_km` и цена/км (для флага аномальной цены). |
| **Кластер** {map-cluster} | Карта | Голубой круг с **бейджем-счётчиком** {map-cluster.count-badge} (число объектов). **Числовой контракт (supercluster):** `clusterRadius` ≈ 50px, кластеризация до `clusterMaxZoom` ≈ 15; выше — отдельные пины. Тап → плавный зум к раскрытию (как 2GIS), не скачок. Если точки в **одной координате** не разваливаются доступным зумом — авто-зум до предела, затем превью-список {preview-sheet} (вариант множественного попадания). Если в кластере есть флаг-объекты — амбер-кольцо {map-cluster.flag-indicator} с «!»-точкой (флаг не теряется при сворачивании). Кластеры пересобираются на каждом уровне зума. |
| **Нижний лист превью** {preview-sheet} | Карта | Приходит снизу при тапе по маркеру/линии/кластеру-без-разворота. Детенты: **peek** (мини-карточка) → **half** (полная мини-карточка + флаги) — свайп вверх; свайп вниз / тап вне листа закрывает, маркер снимает выбор. Внутри — мини-карточка контракта (или превью-список при множественном попадании) + {source-link}. Один уровень глубины. Focus-trap + возврат фокуса — см. Accessibility Floor. |
| **Чип фильтра** {filter-chip} | Поиск/фильтры | Пилюля; тап переключает выбран/невыбран. **Выбранный** — насыщенная заливка {filter-chip.selected-background} + белый текст + **галочка «✓»** перед текстом (не-цветовой признак, WCAG 1.4.1), не бледный {primary-soft}. Применение немедленное (без кнопки «Применить»), список и карта пересобираются; повторный тап снимает чип. Хитбокс ≥ {tap-target}, видимый {focus-ring}. Мок: [`mockups/key-search-filters.html`](mockups/key-search-filters.html). |
| **Ссылка-первоисточник** {source-link} | Все карточки, превью, методика, OG/пуш-подпись | «Первоисточник: goszakup.gov.kz ↗», цвет {link-on-sunken} (AA на surface и surface-sunken), всегда подчёркнута. Открывает оригинал в goszakup (новая вкладка, `rel=noopener`). Якорь доверия на каждой поверхности с доменными данными; на карточке подрядчика — по одной на **каждую** репутационную метку. |
| **Метка «подтверждено»** {confirmed-tag} | Рядом с {source-link} | «Данные из первоисточника» с глифом «✓» {confirmed-text}. Не-цветовой признак «✓»; не «зелёный светофор». Декларативна, не интерактивна. |
| **Фокус-ринг** {focus-ring} | Все интерактивные цели | Видимое кольцо {focus-ring} ширины {focus-ring-width} с офсетом {focus-ring-offset}, ≥3:1 в обеих темах, **на каждой** интерактивной цели включая маркеры карты и сегменты переключателей. Нативный браузерный ринг не используется (теряется на голубоватом sunken). |
| **Переключатель языка** {lang-switch} | Шапка (глобально) | Сегмент-пилюля KZ / RU. KZ активен по умолчанию. Тап переключает язык всего интерфейса; **выбор запоминается** (localStorage + по возможности URL/cookie для серверного OG-рендера). Доменные KZ-поля подтягиваются по выбранному языку (см. предусловие в Foundation). |
| **Переключатель темы** {theme-switch} | Шапка/настройки | Тумблер солнце/луна. Светлая по умолчанию; ручное переключение на тёмную; выбор запоминается; уважает системную `prefers-color-scheme` как стартовое значение. |
| **Орнамент-разделитель** {ornament-divider} | Заголовки секций карточки/района | Тонкий мотив қошқар мүйіз как смысловой разделитель. Чисто декоративен: `aria-hidden`, без интерактива. |

Поведение {data-state-nodata}, {data-state-insufficient}, {data-state-ungeocoded} как
компонентов прописано в State Patterns → «Четыре состояния данных».

**Деконфликт и приоритезация маркеров при плотности (NFR-2, синхронно с z-priority DESIGN.md).**
- **z-order отрисовки/перекрытия:** выбранный {map-marker-selected} (z 3) > флаг {map-marker-flagged}
  (z 2) > подтверждён/обычный (z 1). Флаг-маркеры всегда поверх обычных, чтобы ключевая ценность
  не тонула; выбранный — всегда поверх флага.
- **Collision/declutter:** при перекрытии меток приоритет видимости — у более высокого z; при
  слишком высокой плотности объекты **кластеризуются раньше** (понижается порог разворота), а не
  превращаются в «стену пинов».
- **Гардрейл:** приоритет флага — про **читаемость**, не про «тревогу»: амбер-пин не делается
  визуально громче голубого (см. Inspiration & Anti-patterns).

## State Patterns

### Четыре состояния данных (несущая дисциплина честности)

| Состояние | Где | Поведение / трактовка |
|---|---|---|
| **Данные есть** | Любое поле/флаг | Показываем значение. Доменный текст — на выбранном языке (KZ дефолт). |
| **«Нет данных»** {data-state-nodata} | Отсутствующее поле (срок, BIN, сумма…) | Курсив, {muted-text}: «нет данных» / «деректер жоқ». Никогда не «0» и не прочерк-маскировка. |
| **«Недостаточно сопоставимых данных»** {data-state-insufficient} | Флаг/медиана при недостаточной группе сопоставимости | Плашка {muted-soft} со **сплошным** нейтральным бордюром и глифом «≈»/«<5» (информативно, НЕ ошибка/варнинг). Флаг **не выставляется**, медиана **не показывается**. **Пороги разделены** (data-model, не схлопывать): медиана/цена — `median.min_sample = 5` по ключу сопоставимости (направление × kato × окно 24 мес); преобладание подрядчика — `flag.monopoly.min_group_contracts = 5` по группе район × направление. Значения совпадают сегодня (5), но это **две разные настройки**. |
| **«Объект не геопривязан»** {data-state-ungeocoded} | Объект без координат | Мета-текст + иконка {muted} (перечёркнутый пин — не-цветовой глиф): «без точки на карте» / «картадағы нүкте әзірге жоқ» (не намекает на дефект объекта, а на временный gap данных). Объект доступен в списках/поиске/карточке, но **нет маркера на карте** — честно, без выдуманной точки. |

### Прочие состояния

| Состояние | Поверхность | Поведение |
|---|---|---|
| **Cold load / медленная сеть** | Карта, карточка, список | Скелетоны под ожидаемую раскладку (Айгуль на мобильном интернете), без «спиннер-стены». **Карта (NFR-1, <3с до интерактива):** сначала серый канвас + плашка-скелетон карты (не пустой экран), затем (1) базовые тайлы прогрессивно, (2) объекты по текущему bbox области просмотра (не всё сразу), (3) кластеры/маркеры. Тайл-стратегия — vector tiles + загрузка по требованию; объекты — GeoJSON по bbox. **Карточка/поиск — <1с p95:** скелетон-карточка → данные. Порядок появления: каркас → тайлы → маркеры-кластеры → флаги. |
| **Пустой результат фильтров** | Поиск/список | «Ничего не найдено» + предложение **расширить фильтр** («Попробуйте расширить фильтр» / «Сүзгіні кеңейтіп көріңіз»), с быстрым сбросом одного-двух чипов. Без выдуманных результатов. |
| **Тайлы карты недоступны** | Карта | Первый фолбэк-триггер. Авто → **текстовый список района** (фолбэк-список) + баннер-плашка о причине «Карта временно недоступна — показываем списком». Фильтры/выбранный район сохраняются. |
| **Гео-покрытие района <70%** | Страница района | Второй фолбэк-триггер, операционализирован: покрытие считается **на уровне района** (доля геопривязанных среди объектов района за активный период), источник — **серверный per-район флаг `geo_coverage`** (не клиентский расчёт), пересчитывается при смене фильтров. Срабатывает **на странице района / при входе в район**, НЕ при панораме карты (карта не схлопывается под рукой у пользователя). Пользователь понимает режим по **баннеру** «Этот район показан списком (точек на карте пока недостаточно)». Навигация в фолбэке — через выбор района и поиск; доступен обратный путь «всё равно показать карту». Объекты без точки помечены «без точки на карте». |
| **Агрегат «без точки на карте»** | Карта / страница района | Когда часть объектов района не геопривязана (но порог фолбэка не достигнут) — на карте видимая **аффорданса-счётчик** «Ещё N объектов без точки на карте → открыть списком». Отсутствие на карте честно видно, а не молчаливо (несущий гардрейл честности). |
| **Запись РНУ** | Карточка подрядчика | Факт **государственного** реестра: «Есть запись в государственном реестре (РНУ) — сигнал, требующий проверки», со ссылкой на реестр и **датой записи**. Атрибуция государству, НЕ оценка платформы. **Авто-снятие по `end_date`** записи: после даты окончания флаг исчезает автоматически, не «навечно». Слово «недобросовестный» — только как цитата названия реестра в методике, со ссылкой. |
| **Флаги на неполных данных — НЕ строить** | Карточка подрядчика | Если нормализация в статусе manual/conflict (наименование/BIN не разрешены) — флаги по этому БИН **не выставляются**; показываем «Профиль уточняется» / «профиль нақтылануда». Если флаг уже показан, а профиль ещё дополняется — рядом с флагом оговорка «профиль подрядчика ещё дополняется». Без домысливания пропусков. |
| **Источник недоступен** | Любая карточка | Если ows_v2 недоступен — отдаём данные **из локальной копии** с честной плашкой «Источник временно недоступен — показываем из локальной копии». Никогда не падаем и не выдумываем. |
| **Страница района: пусто / загрузка** | Страница района | Загрузка — скелетон сводки; район без объектов — честное «нет данных по району», без выдуманных медиан (порог сопоставимости применяется к медианам района). |
| **Объяснение методики при недостаточной выборке** | Методика флага | Методика показывает **формулу и пороги всегда**, даже когда сигнал не выставлен; вместо значения сигнала — «недостаточно сопоставимых данных» с указанием, какого порога не хватило (`min_sample`/`min_group_contracts`). |
| **Форма «сообщить об ошибке»** | Форма (с карточки/методики/бота) | Состояния: **пусто** (поля: что не так + контакт по желанию, без обязательного аккаунта) → **заполнение** (валидация инлайн, доступная как текст) → **отправка** (кнопка в состоянии загрузки, защита от двойной отправки) → **успех** («Сообщение отправлено — спасибо», запись падает в Directus-очередь) → **ошибка** («Не удалось отправить — попробуйте ещё раз», данные формы сохранены). Форма достижима рядом с каждым флагом, deep-link из Telegram-пуша. |
| **Фокус (ввод)** | Поиск, форма ошибки, все интерактивные цели | Видимый {focus-ring} (токен DESIGN.md, ≥3:1 в обеих темах), не нативный браузерный ринг. Состояния различаются как текст и форма/глиф, не только цветом. |

## Interaction Primitives

**Карта (центральный примитив).**
- **Pan** — перетаскивание карты (touch drag / мышь).
- **Zoom** — щипок / двойной тап / кнопки зума; **плавно, как 2GIS** (must), без рывков.
  Кластеры {map-cluster} плавно раскрываются при приближении.
- **Tap** — по маркеру/линии → превью-лист; по кластеру → зум к раскрытию (или превью-список
  при совпадающих координатах); по пустому месту → закрытие листа и снятие выбора; по полигону
  района → страница района.

**Контролы карты и досягаемость одной рукой (mobile-first).**
- Зум-контролы (+/-) — в **нижней** зоне экрана (зона большого пальца), хитбокс ≥ {tap-target}.
  Набор MVP: зум +/-, «вернуть к Астане». «Моё местоположение»/компас — за рамками MVP.
- При открытом {preview-sheet} контролы зума **сдвигаются вверх** над листом, не перекрываются.

**Жестовая модель (разведение конфликтов карта ↔ лист ↔ скролл страницы).**
- Вертикальный скролл страницы и pan карты разведены: на встроенной карте — **cooperative
  gestures** (one-finger-pan активирует карту в её зоне; жест вне карты скроллит страницу).
- {preview-sheet}: свайп по листу управляет его **детентами** (peek → half), свайп вниз за
  пределом нижнего детента закрывает; pan карты под листом не перехватывается свайпом листа.
- Приоритет жеста определяется зоной касания (лист > карта > страница).

**Цели и доступность ввода.**
- Все интерактивные цели ≥ {tap-target} (44px): мелкие маркеры (расширенный хитбокс вокруг
  пина), кластеры, чипы, сегменты переключателей KZ/RU и темы, зум-контролы.
- **Клавиатурная навигация:** Tab по интерактивным элементам в порядке чтения; Enter/Space
  активируют; Esc закрывает верхний слой (лист превью, объяснение методики) с возвратом фокуса
  на триггер. Карта управляема с клавиатуры (стрелки — pan, +/- — zoom); **фокус по маркерам —
  через доступный список объектов в кадре**, не обходом тысяч пинов Tab'ом (см. Accessibility Floor).

**Действия.**
- **Поделиться** — кнопка шаринга на карточке контракта/подрядчика: копирует ссылку /
  вызывает системный share-sheet; ссылка несёт серверный OG-рендер для корректного превью в
  мессенджере (см. Responsive & Platform). Текст превью — нейтральный (суффикс «сигнал,
  требующий проверки») + ссылки на методику и первоисточник (гардрейл FR-23).
- **Применение фильтров** — немедленное по тапу чипа {filter-chip} (без кнопки «Применить»);
  сброс одного чипа — повторный тап.
- **Переключение языка** {lang-switch} — мгновенно перерисовывает интерфейс KZ↔RU, выбор
  запоминается.
- **Переключение темы** {theme-switch} — мгновенно светлая↔тёмная, выбор запоминается.

**Движение.** Карта плавная как 2GIS (минимально-необходимо), UI-микроанимации функциональны.
**Уважать `prefers-reduced-motion`:** при включённом — отключаются/сокращаются анимации карты
(зум/раскрытие кластера — мгновенные), переходов и появления листа {preview-sheet}; декоративное
движение убирается полностью.

**Запрещено везде:** карусели, hero-анимации на входе, бейджи-счётчики, тревожные звуки/вибро
на флагах, hover-only аффордансы на тач-вьюпортах, модальные стеки глубже одного уровня.

## Accessibility Floor

Поведенческая доступность. Визуальный контраст — в `DESIGN.md` (все текстовые и UI-пары
проверены против **WCAG 2.1 AA** в обеих темах; см. раздел Colors там).

- **Контраст ≥ AA** в светлой и тёмной темах — обеспечен токенами `DESIGN.md` (нормальный
  текст ≥4.5:1, крупный/UI ≥3:1). Спайн опирается на эти проверки, не дублирует значения.
- **Клавиатура / Tab:** каждый интерактивный элемент достижим Tab в порядке чтения; Enter/Space
  активируют; Esc закрывает верхний слой; видимый {focus-ring} (токен DESIGN.md, не нативный
  браузерный ринг — он теряется на голубоватом sunken) на **всех** интерактивных целях.
- **Различение статусов не только цветом (WCAG 1.4.1):** статус маркера несёт **форма/глиф** —
  пустой пин {map-marker-point}, «!» {map-marker-flagged}, «✓» {map-marker-confirmed}, двойное
  кольцо {map-marker-selected}; выбранный чип — галочка «✓»; состояния данных — свой глиф. Цвет
  вторичен.
- **Доступность canvas-карты MapLibre (механизм, не декларация).** MapLibre рисует на `<canvas>`,
  где маркеры по умолчанию не в дереве доступности. Поэтому:
  - **Постоянный** (не только аварийный) **текстовый список объектов в кадре** — параллельный
    доступный эквивалент карты: ARIA-список (`role=list`/`listitem`) объектов текущего bbox, с
    фокус-таргетами ≥ {tap-target}. Это, а не обход тысяч пинов Tab'ом, — клавиатурный путь к
    маркерам.
  - Интерактивные маркеры реализуются DOM-узлами (`maplibregl.Marker` с `<button aria-label>`),
    а не canvas-символами, чтобы получать фокус и объявляться скринридером.
  - **Объявление выбранного объекта:** при выборе маркера/строки списка SR объявляет объект и
    статус («Объект с флагом — сигнал, требующий проверки. {название}»). Сама карта — `aria-label`
    «Карта Астаны» + подсказка про список как эквивалент.
- **Focus-trap и возврат фокуса (модальные слои).** {preview-sheet} и модалка методики —
  `role=dialog`/`aria-modal`, заголовок слоя как accessible name. При **открытии** фокус
  переносится в слой; внутри — focus-trap; при **закрытии** (Esc / свайп / тап вне) фокус
  возвращается на **триггер** (маркер или {flag-badge}). Без проваливания под лист.
- **Alt у значимых изображений и маркеров:** маркеры несут текстовую альтернативу (объект +
  статус флага); чисто декоративный орнамент {ornament-divider} — `aria-hidden`.
- **Скринридер:** при навигации объявляется текущая поверхность («Контракт: {название}»,
  «Подрядчик: {название}»); бейдж флага объявляет полную нейтральную формулировку; состояния
  данных читаются как текст («нет данных»), не как пустота.
- **Языковые атрибуты (KZ/RU).** `lang="kk"` на `<html>` при KZ-интерфейсе, `lang="ru"` при RU;
  **inline-фрагменты на другом языке** (RU-наименование goszakup внутри KZ-карточки — см.
  предусловие Foundation) помечаются своим `lang`, иначе SR-движок неверно озвучит казахскую
  кириллицу (ә ғ қ ң ө ұ ү і). Переключатель языка обновляет `lang` и **доступен с клавиатуры**.
- **`prefers-reduced-motion`:** анимации карты (зум/раскрытие кластера), переходов и листа
  {preview-sheet} отключаются/сокращаются; никакой декоративной анимации.
- **Размеры целей** ≥ {tap-target} (44px) везде, включая маркеры, кластеры, бейджи, чипы и
  сегменты переключателей KZ/RU и темы (несмотря на 9.5px-кегль label-caps).

> **Уровень MVP — честно:** доступность проверяется **ручным smoke-тестом** (NFR-7).
> Формального WCAG-аудита на MVP **нет**. Это сознательный объём пилота, не претензия на полное
> соответствие. Smoke-чек включает три дешёвые проверки, закрывающие найденное ревью почти
> бесплатно: (а) прогон axe/Lighthouse по одной странице (контраст/lang/имена), (б) проход
> всего флоу только с клавиатуры, (в) один проход скринридером по карте+карточке.

## Карта: режимы и поведение

Мок (карта + фолбэк-список): [`mockups/key-map.html`](mockups/key-map.html).

- **Режим карты (дефолт):** маркеры/кластеры/линии Астаны; плавный зум и pan; KATO-привязка
  объектов. Геопривязанные объекты — на карте; негеопривязанные — только в списках с меткой
  «без точки на карте». На карте видна **аффорданса-счётчик** негеопривязанных объектов района
  («Ещё N объектов без точки на карте → открыть списком»).
- **Два фолбэк-триггера** (механика — в State Patterns, строки «Тайлы карты недоступны» и
  «Гео-покрытие района <70%»):
  1. **Тайлы недоступны** — авто-фолбэк в список района + баннер «Карта временно недоступна».
  2. **Гео-покрытие района <70%** — срабатывает **на странице района / при входе в район**, НЕ при
     панораме карты: карта не «схлопывается» под рукой у пользователя, который уже на ней.
- **Навигация в фолбэке** — через выбор района (полигоны/список) и поиск; всегда доступен обратный
  путь «всё равно показать карту».
- **Переход между режимами** — честный (баннер о причине), без потери выбранного района/фильтров.
- **Полигоны районов и выбор района.** На карте отрисованы границы именованных районов Астаны
  (Алматы, Сарыарка, Есиль, Байконыр, Нура) как полигоны по KATO; ховер/выбор полигона —
  подсветка; **тап по полигону → страница района** (переход карта↔страница района). Альтернатива
  выбору — селектор/чип района и список. Текущий район пользователя читается из подсвеченного
  полигона.

## Поведение риск-флагов

Все четыре флага формулируются как «сигнал, требующий проверки» — описание наблюдаемого факта,
не юридический вывод. Мок объяснения методики: [`mockups/key-flag-methodology.html`](mockups/key-flag-methodology.html).

| Флаг | Факт (нейтрально) | Порог / окно | Что НЕ утверждается |
|---|---|---|---|
| **Один участник в объявлении** | «В объявлении зафиксирован один участник» | Источник — данные закупки | НЕ «сговор», НЕ «неконкурентность». Участие одного поставщика законно по ряду оснований. **Carve-out:** флаг **не выставляется** для способов закупки из `flag.single_participant.exclude_methods` (где один источник законен — из одного источника и т.п.). |
| **Аномальная цена за км** | «Цена за км отклоняется от медианы» (медиана × 1.5) | `median.min_sample = 5`; окно медианы — **24 мес, скользящее**; ключ сопоставимости — **направление × kato × окно 24 мес** | НЕ «завышение». UI-фильтр «период» в поиске (напр. 12 мес) — это фасет поиска, **не** окно медианы. |
| **Преобладание подрядчика в районе** | «Доля одного БИН ≥50% по сумме в группе район × направление» | `flag.monopoly.min_group_contracts = 5` (группа район × направление) | НЕ «монополия» в смысле закона РК о защите конкуренции, НЕ доминирующее положение. Методика прямо оговаривает: «доля по выборке платформы, не вывод о доминировании». |
| **Запись в гос. реестре РНУ** | «Есть запись в государственном Реестре недобросовестных участников (РНУ)» + ссылка на реестр + **дата записи** | Источник — гос. реестр | Атрибуция **государству**, НЕ оценка платформы. «Недобросовестный» — только цитата официального названия реестра в методике, не ярлык подрядчику. |

- **Простота — намеренно:** формулы воспроизводимы вручную (цена = медиана×1.5, доля ≥50%, не
  статистический MAD), чтобы третья сторона могла пересчитать. Объяснение методики показывает
  формулу, пороги, ключ сопоставимости, evidence, `methodology_version` и **дату расчёта**.
- **Пороги разделены (не схлопывать в один «<5»):** `median.min_sample = 5` (медиана/цена) и
  `flag.monopoly.min_group_contracts = 5` (преобладание) — **две разные настройки** для разных
  групп сопоставимости. При недостатке группы флаг **не выставляется** — вместо него
  «недостаточно сопоставимых данных» {data-state-insufficient}.
- **Не строить флаги на неполных/неразрешённых данных:** если нормализация наименования/БИН в
  статусе manual/conflict — флаги по этому БИН не выставляются (показывается «профиль уточняется»).
- **Давность сигнала — у всех четырёх флагов.** Показывать дату/период расчёта (`detected_at`:
  «сигнал по контракту от {дата}»), чтобы старый сигнал не читался как текущая характеристика лица.
  Для РНУ дополнительно — **авто-снятие по `end_date`** записи реестра (флаг не вечен).
- **Цвет — только нейтральный амбер** {signal-attention}; статус несёт прежде всего **глиф «!»**
  ({flag-badge} / {map-marker-flagged}), цвет вторичен. Тревожно-алый запрещён. Зелёный/красный
  «светофор» зарезервирован под будущий «светофор регионов» и к флагам не применяется.
- **Защитные связи у каждого флага** (см. «Правило достижимости защитных связей»): путь к методике
  /пересчёту и канал «Сообщить об ошибке» доступны рядом с флагом на каждой поверхности, включая
  OG-превью и Telegram-пуш.

## Responsive & Platform

**Mobile-first → десктоп.**

| Брейкпойнт | Поведение |
|---|---|
| Mobile (дефолт) | Одна колонка; карта на основную высоту; контракт — нижний лист {preview-sheet}; поиск/фильтры — полноэкранный слой. |
| Десктоп (широкий экран) | Карта + боковая панель: список/фильтры уходят вбок; контентная колонка остаётся одноколоночной и читаемой (не растягивается в неудобную ширину). Превью может показываться попапом на карте, но поведение тапа то же. |

**Telegram-бот как поверхность.** Мок: [`mockups/key-telegram-bot.html`](mockups/key-telegram-bot.html).
Подписка на район, пуш о новом контракте/флаге, смена/отписка,
**антифлуд-дайджест** (сгруппированные уведомления вместо потока). Deep-link из бота открывает
страницу района/контракта в вебе. **Пуш/дайджест с флагом обязан нести** (FR-23, гардрейл §7.1):
нейтральную формулировку с суффиксом «сигнал, требующий проверки», ссылку **«Как это посчитано»**
(методика/пересчёт), ссылку на первоисточник goszakup и **deep-link на форму «Сообщить об ошибке»**.
Голое утверждение о лице в пуше запрещено.

**OG-теги — серверная отдача.** Для корректного превью при шаринге в мессенджеры/соцсети теги
Open Graph отдаются **сервером** (не клиентским JS), чтобы кравлеры увидели заголовок/сумму. Это
требование к серверному OG-рендеру, не «формулировка нейтральная» как единственная гарантия:
OG-превью с флагом несёт (а) нейтральную формулировку с суффиксом, (б) рабочие ссылки на
**первоисточник** и **методику/пересчёт**, (в) упоминание канала «Сообщить об ошибке» в
описании/на целевой странице шаринга. Превью отрисовывается на выбранном языке (см. предусловие
KZ-полей).

**Перформанс-бюджеты (NFR-1):** карта интерактивна **<3с**; карточка и поиск — **<1с p95**.
Скелетоны и системный шрифт-фолбэк страхуют медленную сеть.

## Inspiration & Anti-patterns

**Вдохновение.**
- **2GIS** — взято четыре вещи: (1) **качество карты** — плавность, кластеры, скорость, умное
  поведение при зуме; (2) **плотность без хаоса** — насыщенно, но читаемо; (3) **деловитость/
  утилитарность** — ничего лишнего, всё по делу (источник доверия); (4) **узнаваемый акцентный
  цвет-маркер**.
- **Модель Prozorro / DoZorro** — гражданский контроль закупок: открытые данные, проверяемость,
  переход к первоисточнику. Берём посыл прозрачности и проверяемости, **без** обличительной
  тональности DoZorro.

**Анти-паттерны (явно отвергнуто).**
- **«Сухой госреестр»** — стерильность, безжизненность, канцелярщина. Платформа официальна, но
  человечна и живая.
- **Тревожно-алый «виновен» на флагах** — запрещён; флаг = нейтральный амбер «сигнал, требующий
  проверки».
- **Амбер-пин как «горячая точка»** — амбер-маркер {map-marker-flagged} отличается **глифом «!»**,
  а не «громким» цветом: его визуальная весомость **равна** голубому. Делать амбер-пин ярче/крупнее
  голубого (светофорная «тревога» до прочтения текста) — запрещено; цветовое выделение по БИН без
  не-цветового признака и текста создаёт обвинительный визуальный сигнал.
- **Фолк-перегруз орнаментом** — қошқар мүйіз только тонким разделителем, не фон-заливкой
  рабочих экранов.
- **Обличительный / оппозиционный тон** — никаких «разоблачений», призывов против лиц,
  тревожной риторики.

## Key Flows

Три именованных публичных сценария (Айгуль, Ержан, Данияр) покрывают UJ гражданина, подписчика и
журналиста. **Операторский поток (UJ-4: геопривязка UC-09/UC-10, нормализация в Directus)
сознательно вне публичных Key Flows** — Directus описан как внутренний инструмент, гражданин его
не видит. Краткий внутренний путь оператора: очередь негеопривязанных/неразрешённых объектов →
ручная геопривязка/нормализация → объект получает точку/разрешённый профиль (до этого флаги по
нему не строятся, см. «Поведение риск-флагов»).

### Flow 1 — Айгуль (гражданка, ~10 секунд, телефон)

Моки: [`mockups/key-map.html`](mockups/key-map.html), [`mockups/key-contract-card.html`](mockups/key-contract-card.html).

1. Айгуль открывает ссылку на телефоне; карта Астаны загружается (скелетон → интерактив <3с).
2. Находит **свою улицу**, видит маркер ремонта дороги рядом с домом.
3. Тапает по маркеру → снизу приходит **превью-лист** {preview-sheet} с мини-карточкой:
   название объекта, сумма {amount}, подрядчик.
4. Тапает «Подробнее» → **карточка контракта** {contract-card}.
5. Видит **бейдж флага** {flag-badge}: «В объявлении зафиксирован один участник — сигнал, требующий
   проверки» (нейтральный амбер с глифом «!», не тревога).
6. Рядом — {source-link} «Первоисточник: goszakup.gov.kz ↗» и ссылка «Сообщить об ошибке»: данные
   не выдуманы, у факта есть канал возражения.
7. **Кульминация:** контракт у дома понятен и проверяем. Айгуль тапает «Поделиться» — ссылка с
   серверным OG-превью уходит в чат нейтральной карточкой, без слова «нарушение».

*Сбой:* объект без координат → нет маркера, но он находится через поиск и помечен «без точки
на карте» {data-state-ungeocoded}. Медленная сеть → скелетоны, не пустой экран.

### Flow 2 — Ержан (подписчик, Telegram)

Мок: [`mockups/key-telegram-bot.html`](mockups/key-telegram-bot.html).

1. Ержан открывает **Telegram-бот** AshyqQala.
2. Выбирает **свой район** из списка (подписка).
3. Позже приходит **пуш**: новый контракт/флаг по его району — нейтральная формулировка «сигнал,
   требующий проверки» + ссылки «Как это посчитано», первоисточник и deep-link «Сообщить об ошибке»
   (не голое утверждение).
4. При активности района бот шлёт не поток, а **антифлуд-дайджест** — сгруппированную сводку.
5. Ержан переезжает и **меняет район** одной командой (или отписывается).
6. **Кульминация:** он в курсе того, что строят рядом, **не заходя на сайт** — гражданская
   осведомлённость приходит сама, без шума.

*Сбой:* всплеск событий → дайджест защищает от флуда; deep-link из пуша открывает страницу
района в вебе для деталей.

### Flow 3 — Данияр (журналист/исследователь)

Моки: [`mockups/key-flag-methodology.html`](mockups/key-flag-methodology.html), [`mockups/key-district.html`](mockups/key-district.html).

1. Данияр открывает **поиск/фильтры**, ставит чипы {filter-chip}: направление = **дороги**,
   период = **12 месяцев**, **есть флаг**.
2. Список пересобирается мгновенно; он открывает контракт с флагом **«Аномальная цена за км —
   сигнал, требующий проверки»**.
3. Тапает по бейджу {flag-badge} → **объяснение методики**: видит, **как построен флаг** (медиана
   × 1.5; ключ сопоставимости — направление × kato × окно **24 мес скользящее**), evidence,
   **дату расчёта** и `methodology_version`; может пересчитать вручную. Замечает, что UI-фильтр
   «период = 12 мес» в поиске — это фасет, **не** окно медианы.
4. Переходит по {source-link} в **goszakup** — сверяет оригинал закупки.
5. Возвращается, открывает **страницу района** → сравнивает медиану района.
6. Из контракта идёт в **карточку подрядчика** → видит запись **в гос. реестре РНУ** (с датой и
   авто-снятием по `end_date`, со ссылкой на реестр) и/или флаг **преобладания подрядчика в районе**
   (доля ≥50% по выборке платформы — не юридическая монополия). У каждой метки — своя
   ссылка-первоисточник и «Сообщить об ошибке».
7. **Кульминация:** перед публикацией у него на руках **проверяемая аномалия** — формула,
   первоисточник, медиана района, дата расчёта — а не голословное обвинение.

*Краевой случай:* для редкого типа работ в районе группа сопоставимости меньше порога
(`median.min_sample = 5` для цены; `flag.monopoly.min_group_contracts = 5` для преобладания —
**разные настройки**) → флаг **не выставляется**, показано **«недостаточно сопоставимых данных»**
{data-state-insufficient}. Данияр понимает: сигнала нет не потому, что всё чисто, а потому что
данных недостаточно для сравнения — и не публикует ложный вывод.
