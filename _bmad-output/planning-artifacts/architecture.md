# Документ архитектурных решений — AshyqQala.kz

## Анализ проектного контекста

### Обзор требований

**Функциональные требования (FR-1…FR-28, 11 блоков):**
- **Импорт и нормализация (FR-1…FR-3):** ежедневный инкрементальный импорт ows_v2
  через `/v2/journal`; нормализация наименований к каноническому БИН (авто + очередь
  оператора, изоляция конфликтов); устойчивость к недоступности и смене схемы API.
- **Геопривязка (FR-4…FR-6):** автоподбор точки/района по адресу/КАТО; полуручная
  разметка POINT|LINESTRING через Directus; Go/No-Go-гейт автопокрытия ≥70% с фолбэком.
- **Публичная карта (FR-7…FR-9):** маркеры/кластеры/полилинии (MapLibre), превью,
  фолбэк-список района (серверный per-район `geo_coverage`).
- **Карточки контракта/подрядчика (FR-10…FR-14):** поля контракта, первоисточник,
  акт (дата+подписант), активные флаги; агрегаты подрядчика по БИН, метка РНУ.
- **Поиск/фильтрация (FR-15, FR-16):** фасеты + поиск по БИН/наименованию.
- **Страница района (FR-17, FR-18):** агрегаты; медиана ₸/км, сравнение «район vs город».
- **Флаги риска (FR-19…FR-23):** 4 пересчитываемых флага на конфиге methodology_params.
- **Telegram-бот (FR-24…FR-26):** подписка на район, уведомления, антифлуд-дайджест.
- **Шаринг (FR-27):** серверный OG-рендер (двуязычный, нейтральный, с защитной связью).
- **Сообщение об ошибке (FR-28):** публичный безаккаунтный досудебный канал → Directus.

**Нефункциональные требования (драйверы архитектуры):**
- **NFR-1 Перф:** карта <3с, карточка/поиск <1с p95 → vector tiles, bbox-загрузка,
  скелетоны, серверный OG. Бюджет с ДВУМЯ числами: эталон + p95 на медленном устройстве/
  сети (3G, старый Android); деградация list-first.
- **NFR-2 Масштаб:** сотни–низкие тысячи контрактов; 1000+ MAU; 1500+ подписок; один VPS.
  Sizing считать из выхода stage0-audit (OQ-1), не угадывать.
- **NFR-3 Доступность/свежесть:** публичная часть выдаётся из локальной копии при
  недоступности ows_v2. ВАЖНО (раунд 2): локальная БД — это ПРОЕКЦИЯ/КЭШ, перестраиваемая
  из снапшотов journal, а НЕ источник правды (источник правды — goszakup). Следствие:
  пережить отказ обязан маленький иммутабельный снапшот-стор (дешёвый оффсайт-бэкап), а
  RPO/RTO считаются от времени перестроения проекции, а не как для незаменимых данных.
- **NFR-4 Наблюдаемость:** slog + /metrics; import_runs; счётчики SM-C1/SM-C2 как
  тестируемые хуки в /metrics.
- **NFR-5 Прослеживаемость:** первоисточник в каждой карточке; каждый флаг пересчитываем.
- **NFR-6 i18n → ПЕРЕОПРЕДЕЛЁН (EXPERIENCE.md):** язык по умолчанию — КАЗАХСКИЙ. Разрешение
  противоречия «KZ по умолчанию ↔ данные RU» (раунд 2): язык — свойство РОЛИ строки.
  UI-хром = НАШ голос (казахский). Доменный факт (name/subject из goszakup) = ЦИТАТА
  первоисточника → переводить молча ЗАПРЕЩЕНО; помечаем `lang` источника, показываем как
  есть с явной меткой языка. Машинный перевод цитат — опционально и позже, как видимая
  оспоримая интерпретация (не несущее для MVP).
- **NFR-7 Адаптивность/доступность:** mobile-first; WCAG 2.1 AA; a11y canvas-карты
  (DOM-маркеры + ARIA-список). Список объектов — равноправное представление данных, не
  проекция карты (он честен к негеокодированному контракту, карта — нет); объекты без
  геокода обязаны быть в списке.
- **NFR-8 Качество данных:** полнота (сумма/адрес/акт), дедупликация, актуальность.

### Архитектурная точка рычага (центральная находка ревью)

**Иммутабельный адресуемый снапшот — первоклассная сущность, над которой определено всё
остальное.** Это разрешает центральное физическое противоречие системы: «флаг должен быть
воспроизводим (входы заморожены) ↔ платформа должна быть свежей (входы меняются ежедневно)».
Решение — разделение во времени: флаг считается над СНАПШОТОМ на момент T; воспроизводимость
= «дай то же `(snapshot_id, methodology_version)` → получи тот же результат бит-в-бит».
Один сдвиг роняет четыре проблемы: пересчитываемость (заморозка + поток снапшотов);
надёжность одного VPS (БД → кэш-проекция, а не правда); честность пустоты (она датирована
снапшотом: «в снапшоте T поля не было»); двуязычие (цитата привязана к снапшоту-источнику →
переводить нельзя по построению).

### Сквозные заботы и архитектурные опоры

1. **Снапшот как фундамент** (см. выше): иммутабельный, адресуемый; БД-выдача — его
   производная. Открытый суб-вопрос для решений: ключ снапшота `(объект, дата journal)` vs
   хеш содержимого.
2. **Ядро как чистые функции:** `flag(inputs, params)`, `median(samples, scope, params)`,
   `normalize→BIN` — без обращений к БД внутри; кэш медиан price_benchmarks — производное от
   функции (одна истина), пересчёт «в сторону → атомарный swap».
3. **Контракт пересчитываемости = иммутабельная модель данных, а не фича:** evidence хранит
   ВСЕ входы (сумма, медиана, размер выборки, район/город, пороги) + `(snapshot_id,
   methodology_version)`; methodology_params — ВЕРСИОНИРУЕМЫЙ ИММУТАБЕЛЬНЫЙ конфиг (правка =
   новая версия, история не переписывается → требование к DDL до первой записи); одна
   реализация формул для онлайн-пересчёта И публичного калькулятора; внешний пересчёт
   (намеренно на другом языке) даёт тот же вердикт.
4. **Документация/строки как контракт, генерируемые из единого источника** (методика — это
   API, не README): проза методики ВСТАВЛЯЕТ константы из methodology_params (не дублирует);
   тексты методики «для гражданина» и «для журналиста/юриста», подписи UI и значения enum
   честных состояний — из одного источника; CI-тесты: запретный лексикон в ОБЕИХ локалях,
   объяснение каждого ключа params в обеих, сверка снимка ows_v2 с `-probe`. Объяснимость
   (человек повторяет расчёт на бумаге) важнее одной лишь верифицируемости — отсюда простая
   формула ×1.5, показ арифметики с реальными числами и знаменателя выборки, блок «чего флаг
   НЕ значит».
5. **Честные состояния — типизированный enum API** (общий для web/OG/Telegram), две РАЗНЫЕ
   оси: полнота входа (`нет данных`) vs мощность метода (`недостаточно сопоставимых данных`);
   плюс `нет геокода`, `данные на другом языке`, `данные устарели (с <дата>)`,
   `флаг не публикуется`. Флаг имеет состояния RAISED / NOT_RAISED / INSUFFICIENT_DATA.
6. **Нейтральность — свойство флага, gate на сервере:** «нет пути к методике + каналу
   „Сообщить об ошибке" → флаг НЕ публикуется» — единый серверный gate в момент отдачи для
   ВСЕХ каналов; OG/пуш — рендеры одного источника, не вторые стражи. На OG-артефакте —
   видимый короткий URL/QR + версия методики (скриншот переживает пересылку).
7. **Достижимость защитной связи + право на возражение:** стабильный вечный короткий
   идентификатор флага/контракта; поле «получено возражение/ссылка» в модели уже на MVP
   (нейтральность материализована, не декларативна).
8. **Идемпотентный импорт + атомарная публикация:** повторный прогон не создаёт дублей
   (UNIQUE + upsert); читатель видит снапшот целиком (старый или новый), не полупересчёт;
   единая граница декодирования API с ЗАФИКСИРОВАННЫМ контрактом схемы (маппинг из
   fieldCandidates переиспользуется, но политика инвертируется: аудит=тихо → прод=стоп+алерт
   на изменение зафиксированного контракта); golden-снапшот ответа ows_v2 + тест декодера.
9. **Разделение владения данными:** импортёр и Directus НИКОГДА не владеют одними колонками;
   ручные правки (geo manual/conflict, bin_resolution, перевод) в полях, которые переимпорт
   не трогает и уважает.
10. **Read-модели для выдачи** материализуются заранее; пиковый пересчёт изолирован от
    дневного трафика; вход через расшаренную ссылку (deep-link на карточку + SSR/OG) —
    основной маршрут, не побочный.
11. **Корректность данных (reconcile + границы):** район по КАТО без геоточки; не флагать/не
    агрегировать неразрешённый БИН (manual/conflict); медиана «район vs город» с фиксацией в
    evidence, какая использована; граничные выборки n=0/1/2 → «недостаточно», не NaN.

### Промежуточное отклонение (2026-06-20): временный парсер-источник

> **Внесено Sprint Change Proposal 2026-06-20 (решение владельца Bratan).** ВРЕМЕННОЕ отклонение
> от несущего принципа §6.1/§6.4 («официальный канал, не парсинг») и от «скрейпинг невозможен по
> структуре» (строки 94–96, 275–276, 395). Владельцу явно показан конфликт и более чистая
> альтернатива (синтетика Epic 1); решение принято осознанно.

Владелец санкционировал временное использование `tools/scrape` как источника **лотов** до
получения `GOSZAKUP_TOKEN`. Ограничения отклонения (минимизация урона):

- **Только лоты.** Договоры/участники/РНУ/акты/journal недоступны без авторизации → карточки,
  3/4 флага и медианы **ждут токен**.
- **За флагом** `ASHYQQALA_INTERIM_SCRAPE`; интерим-импорт — отдельная `tools/`-команда **вне**
  `cmd/api`/`cmd/importer` (горячий путь чист); CI-страж: прод-бинарь не импортирует `tools/scrape`.
- **Обратимость.** Переиспользуется `Source` (`ows|file|scrape`) и тот же downstream
  (`decode → lots → geo → map`) → переключение `scrape → ows` = один флаг; работа не выбрасывается.
- **Keyword-bias.** Выборка scrape отобрана словами направлений → доля направлений непоказательна
  (метить «предв.»).

**Критерий удаления / путь восстановления:** при получении токена — `Source` scrape→ows; выключить
флаг и удалить интерим-команду; восстановить структурный запрет §6.1/§6.4; прогнать гейт №0
(Epic 0); Epic 2 живой импорт замещает scraped-лоты. **Юр-риск активен СЕЙЧАС** (реальный парсинг) —
владелец риска назначается в Story 0.9.

## Starter Template Evaluation

### Primary Technology Domain

Full-stack web с разделёнными поверхностями: Go-бэкенд (публичный API + ETL-конвейер +
OG-рендер + Telegram-бот), React/Vite SPA (карта MapLibre, карточки, поиск), Directus как

### Контракты-как-код: единый позвонок `registry/` + перекрёстный гейт

Четыре «генерируемых из источника» контракта (methodology_params, tokens, OpenAPI, snapshot-
schema) НЕ должны стать четырьмя правдами. Позвонок — **`registry/` (человек правит ТОЛЬКО
здесь):** `methodology_params.vN.yaml` (иммутабельный) · `honest_states.yaml` · `glossary.yaml
{key→kz,ru}` · `taboo_lexicon.yaml`. Из них генерятся: OpenAPI-enum честных состояний; цвет
бейджа в tokens (ссылается на `honest_state.key`); ключи i18n; текст методики (константы
шаблоном `{{price_deviation}}`). OpenAPI YAML — рукописный (арбитр) → `openapi-typescript`
(TS-типы фронта) + `kin-openapi` response-валидация в Go-тестах (НЕ генерация из Go-хендлеров).
**Пятый перекрёстный тест на смыкание** (главный анти-дрейф): множества ключей `honest_state`
РАВНЫ в OpenAPI ∩ i18n.kz ∩ i18n.ru ∩ tokens ∩ glossary; `methodology_version` в evidence ==
текущая в params; каждая константа прозы пришла из params; ноль taboo-строк в обеих локалях.
**Воркшит-пересчёт с числами журналиста** + человекочитаемый рендер `evidence` + явный критерий
«похожести» + `as_of`/snapshot-id — обязательные артефакты (человеческий контракт = юр-щит).

## Core Architectural Decisions

### Decision Priority Analysis

**Critical (блокируют реализацию):** PostgreSQL 16 + PostGIS, pgx + sqlc; граница декодирования
ows_v2 + schema-hash; контракт пересчитываемости (evidence + immutable methodology_params);
миграции (goose); провайдер тайлов и геокодер (блокируют карту и гейт №0).
**Important (формируют архитектуру):** проекционные↔кураторские таблицы; единый outbox;
read-модели/кэш медиан со swap; поиск pg_trgm; OpenAPI как исполняемый контракт; registry/;
**hot/cold split сервисов.**
**Deferred (post-MVP):** аутентификация и ПД-контур (этап 5); тяжёлый снапшот-стор; Redis/
Kafka/K8s/ClickHouse; публичный API (этап 6, но домен ⊥ доставки делает его дешёвым); AI-слой;
**свой PMTiles-экстракт (S-0.5/после демо); KZ-стемминг поиска.**

### Data Architecture

- **СУБД:** PostgreSQL 16 + PostGIS 3.x. Доступ — pgx v5 + sqlc 1.31.x (overrides для `geometry`,
  геометрия как WKB/WKT); динамический bbox-запрос карты — pgx-raw в `internal/store/geo.go`.
- **Миграции:** goose (SQL up/down; единый источник истины схемы; sqlc генерит из тех же файлов —
  иначе рассинхрон).
- **Границы данных:** ПРОЕКЦИОННЫЕ ↔ КУРАТОРСКИЕ таблицы с разными грантами; отдельная граница
  «публичные данные goszakup ↔ пользовательский контент» (задел ПД этапа 5).
- **Снапшот (лёгкий):** `snapshot_id` + дешёвый сырой дамп (JSONB/файл). Тяжёлый стор отложен.
- **Кэш:** материализованные read-модели; `price_benchmarks` — пересчёт «в сторону → swap».
  Гео-результаты кэшируются в `geo_objects` (Nominatim после batch не дёргается). Redis НЕ вводим.
- **Район по КАТО** даже без геоточки; негеокодированные — в агрегатах/медиане.
- **Поиск (FR-15/16) — pg_trgm как ОСНОВНОЙ** (substring, language-agnostic: «жол*» → «жолы/
  жолдар» без морфологии; нечёткий поиск RU/KZ через GIN-индексы); **FTS только `simple`** (у
  PostgreSQL НЕТ казахской конфигурации; `russian`-стеммер на KZ = тихая потеря результатов —
  запрещён). **Зафиксировать ICU-коллацию** на колонках поиска (VERIFY: `Қарағанды` матчит
  `қарағанды`). БИН — точный матч. Полноценный KZ-стемминг — явный долг в backlog, не имитация.
- **Валидация:** zod на границах фронта; `decode` + schema-hash на бэке; methodology_params —
  версионируемый иммутабельный конфиг.

### Authentication & Security

- **Аутентификации и ПД-контура НЕТ** (read-only MVP); аккаунты/верификация — этап 5.
- **Изоляция токена:** `cmd/importer` держит `GOSZAKUP_TOKEN` и пишет; `cmd/api` токена не видит.
  Секреты — env/секрет-стор VPS, вне репо; ротация.
- **Гранты БД:** Directus без write к проекционным; импортёр без write к кураторским.
- **Хостинг в РК** (суверенность ДАННЫХ — она в Postgres, не в зоопарке контейнеров);
  `telegram_chat_id` — юр-оценка до запуска бота (OQ-2).
- **Скрейпинг невозможен по структуре** (`scrape.go` в `tools/`, §6.1/6.4).
- **Геокодер self-host** → адреса не уходят наружу (согласовано с суверенностью).

### API & Communication Patterns

- **REST через chi v5.** Контракт — рукописный OpenAPI YAML (арбитр) → `openapi-typescript` +
  `kin-openapi` response-валидация в Go-тестах.
- **Граница декодирования ows_v2:** `internal/decode` + `schema_hash` (detect & halt на
  критичных полях, не тихий 0).
- **Честные состояния — типизированный enum** (web/OG/Telegram): `нет данных`, `недостаточно
  сопоставимых данных`, `нет геокода`, `данные на другом языке`, `данные устарели`,
  `флаг не публикуется`. НЕ HTTP-ошибки.
- **Ответы флагов:** `evidence` (все входы) + `methodology_version` + `as_of`/snapshot_id.
- **Уведомления — единый transactional outbox** (зафиксировано), атомарные задачи:
  - O-1: запись бизнес-объекта + outbox-строки в ОДНОЙ транзакции (откат ⇒ нет ни той, ни той).
  - O-2: воркер поллит неотправленные (`FOR UPDATE SKIP LOCKED`), вызывает `Dispatcher.Send`,
    ставит `sent_at`; на ошибке растёт `attempts`.
  - O-3: дедуп по `event_id` (повтор не двоит у получателя).
  - O-4: retry/visibility-timeout детерминированы через инъекцию `Clock`.
  - Получатель — ИНТЕРФЕЙС: в S-0 `LoggingDispatcher`; Telegram-реализация — S-1.
- **OG-теги** рендерит Go из той же проекции, что и SPA; защитная связь запекается в артефакт +
  серверный gate. **Rate limiting:** базовый на read-API; вежливость к Telegram — троттл outbox.

### Frontend Architecture

- React + Vite + TS. React Router (data, deep-link основной); TanStack Query владеет загрузкой
  (Router-loader не фетчит); client-state минимум (тема/язык в localStorage); zod для URL.
- **Карта** — MapLibre GL 5; **формат тайлов — PMTiles** (статический файл через Caddy, без
  per-load платы и тайл-сервера). **Свой экстракт Астаны — ОТЛОЖЕН (S-0.5/после демо):** для
  раннего демо — готовая база (Protomaps-сборка/MapLibre-стиль) + наши точки векторным слоем
  поверх; свой `astana.pmtiles` (planetiler) — когда будет время/смысл. ⚠ StrictMode →
  `useRef`-guard от двойного `new Map()`.
- **Список объектов — равноправное карте представление** (честен к негеокодированному;
  деградация list-first; a11y-эквивалент canvas-карты).
- **Стили/токены** — CSS Modules + CSS-переменные из `tokens.json` (свой codegen; без Tailwind/
  Style Dictionary); две темы семантическими именами. **a11y** — Radix (механика) + свой визуал;
  focus-ring токеном; гейты axe.
- **i18n** — namespace `chrome` (KZ дефолт ↔ RU) ⊥ данные API (с пометкой языка); `lang`-атрибуты;
  `Intl`. ⚠ MapLibre-попапы — `i18n.t` императивно + `languageChanged`.
- **SSR не используется** (OG делает Go).

### Infrastructure & Deployment

- **Docker Compose + Caddy на одном VPS (РК), сервисы разделены по онлайн-критичности:**
  - **Горячий путь (24/7, обслуживает читателя):** `postgres` (16+PostGIS), `api` (Go), `web`
    (статика Vite за Caddy), PMTiles-файл через Caddy. Лёгкий, предсказуемый, бэкапится,
    переживает демо.
  - **Холодный/пакетный (эпизодически, не в горячем пути):** `importer`, `directus` (профиль,
    поднимать на время курирования), `bot`, **`nominatim`** (профиль compose `geocode`).
- **Геокодер — self-host Nominatim как ЭФЕМЕРНЫЙ BATCH** (НЕ 24/7, НЕ в S-0): osmium-extract
  Астаны по bbox → импорт (`mediagis/nominatim`, урезанный `IMPORT_STYLE`) → batch-геокодинг →
  результат в `geo_objects` → контейнер ГАСИТСЯ. Репликация/обновления для MVP НЕ нужны. Реальная
  стоимость: импорт 30–90 мин, диск 8–20 ГБ, RAM на импорте ≥8 ГБ, ~2 чел-дня на первый зелёный
  импорт. **Альтернатива (если ops тяжёл, по Victor):** managed-геокодер одним batch-проходом →
  координаты в БД → в рантайме внешней зависимости ноль. Решение Bratan — self-host; managed —
  задокументированный fallback.
- **CI** — GitHub Actions, path-фильтры, гейты день-1 (vet/gofmt/tsc; doc-нейтральность; go test
  golden; contract+schema-hash; vitest+контраст; testcontainers `postgis/postgis` с кэшем образа
  и retry; Playwright smoke); красный = блок merge.

### Decision Impact Analysis

**Гейт №0 — уточнение (важно):** гео-метрика = **Шаг B+** (реальный Nominatim), НЕ Шаг B
(гео-прокси по адресному маркеру в имени лота). Фиксировать РАЗДЕЛЬНО: «% распарсенных
адресных строк» и «% сматченных в OSM», плюс **распределение пропусков** (систематический
провал по новостройкам/пригородам Астаны хуже случайного — Айгуль живёт именно там), плюс
ops-baseline (RAM-пик + размер БД Nominatim), плюс заранее оценённый объём ручной гео-очереди
(Directus) как fallback — это переводит риск «<70%» из обрушения в известную стоимость.

**Последовательность реализации:** гейт №0 (токен + stage0 Шаг B+ + B-1) → S-0 walking skeleton
на синтетике (goose/sqlc/testcontainers + outbox с LoggingDispatcher; карта на фикс-координатах

флаги/медианы → карта (PMTiles) + список → страницы районов → поиск (pg_trgm) → Telegram-бот
(outbox→Telegram, S-1) → OG/шаринг → канал «сообщить об ошибке».

**Кросс-компонентные зависимости:** `registry/` питает OpenAPI/i18n/tokens/текст методики (+ 5-й
перекрёстный тест); `snapshot_id` течёт сквозь импорт→флаги→evidence→OG; единый outbox делят
импорт-события и бот; `internal/decode` — единственный гейт входа ows_v2; проекционные таблицы =
функция от снапшота + кураторских правок; Nominatim/PMTiles — пакетные поставщики `geo_objects`/
подложки вне горячего пути.

## Implementation Patterns & Consistency Rules

> Принцип консистентности мульти-агентной разработки: **сужать пространство выбора до
> машинно-проверяемого минимума** — closed lists вместо open grammar, lint как граница,
> обёртки-инкапсуляторы. Что не падает в CI — пожелание, а не паттерн.

### Naming Patterns

**База данных (PostgreSQL):** таблицы snake_case plural; колонки snake_case; PK `id` bigint
identity (внутр.) + natural `goszakup_*_id` UNIQUE; FK `<entity>_id`; геометрия `geom` (SRID 4326);
индексы `idx_<table>_<cols>`, trigram `<table>_<col>_trgm_idx`, GIST `<table>_geom_gist`; миграции
goose `NNNN_*.sql`. **Двуязычные поля — суффикс `_kk` / `_ru`** (`name_kk`, `subject_ru`). НИКОГДА
`_kz` как язык (`kz` = страна/ISO3166; `kk` = язык/ISO639-1).

**API (REST / chi v5):** `/api/<plural>/{id}` (`contracts/{id}`, `contractors/{bin}`,
`districts/{kato}`, `search`, `methodology/{flag_type}`); query snake_case; **JSON snake_case на
проводе** (`json`-тег == OpenAPI-имя == `db`-тег дословно; acronyms lower: `bin/id/kato/iin/url`).
camelCase допустим ТОЛЬКО внутри React за границей API-клиента, не в контракте. Внешне-видимый id
в URL/`subject_ref`/outbox — **natural `goszakup_*_id`** (стабилен между реимпортами); у сущностей
без natural-id (`geo_object`, `risk_flag`) — **UUIDv7** публичный, bigint только внутр. Версия —
префикс `/api` (без `/v1` на MVP).

**Код:** Go — стандарт (пакеты lowercase, экспорт PascalCase, файлы lowercase, `%w`-обёртки,
`context.Context` первым). TS/React — компонент `ContractCard.tsx` + `ContractCard.module.css`;
хук `useContract.ts`; типы API ГЕНЕРЁННЫЕ из OpenAPI (не руками).

### Structure Patterns

- Go-тесты co-located `*_test.go`; golden — `/fixtures/golden`.
- Frontend **по фиче** (`web/src/features/{map,contract,contractor,district,search,flag,share}`) +
  `shared/{ui,api,i18n,tokens}`. **`shared/ui` без доменного знания; фичи компонуют, не рисуют
  (никаких сырых интерактивных элементов — только из `shared/ui`).** TS-тесты `*.test.tsx`;
  E2E `web/e2e/`.
- Корни: `migrations/` · `docs/api-contracts/` (OpenAPI + снапшот ows_v2) · `registry/` (см. ниже)
  · `deploy/` · `fixtures/` · `tools/`.

### Format Patterns (wire-правила, citable)

- **Честные состояния — НЕ ошибки** (HTTP 200 + типизированный enum), разнесены на **ДВЕ ОСИ:**
  - `value_state` (почему нет ЗНАЧЕНИЯ): `ok` · `no_data` · `insufficient_sample` ·
    `not_comparable` · `stale` · `geocode_pending` · `geocode_failed` · `source_conflict` ·
    `redacted` · `not_applicable` · `error`.
  - `flag_state` (почему нет/есть ФЛАГА): `raised` · `not_raised` · `insufficient_data` ·
    `not_published`.
  - Закрытый union; рендер ОБЯЗАН иметь default-ветку (новое состояние → явное «неизвестно, см.
    методику», не «пусто»). HTTP 4xx/5xx — только технические сбои: `{"error":{"code","message"}}`.
- **Error-коды** — UPPER_SNAKE закрытый каталог (`NOT_FOUND`, `VALIDATION_FAILED`,
  `INVALID_CURSOR`, `RATE_LIMITED`, `INTERNAL`) в `internal/apierr/codes.go` + зеркало OpenAPI +
  i18n (двуязычны, см. registry); `message` — ru, не для парсинга.
- **Деньги** — `bigint` целые тенге, суффикс `_tng`; **в JSON СТРОКА** (`"amount_tng":"1234567890"`
  — bigint > 2^53 теряет точность в JS); формат — `Intl.NumberFormat`.
- **Даты/время** — хранение `timestamptz` UTC; провод ISO8601 с `Z`; даты-без-времени — тип `date`
  / `YYYY-MM-DD`; бизнес-локаль Asia/Almaty только на презентации (`Intl.DateTimeFormat`).
- **Геометрия** — наружу всегда **GeoJSON RFC7946**, порядок **`[lon, lat]`** (НЕ `[lat,lon]`!),
  `ST_AsGeoJSON(geom)::jsonb`, SRID на проводе не пишем (всегда WGS84).
- **Двуязычный контент** — объект `{value, lang, is_fallback, resolution}`: `lang ∈ {"kk","ru"}`
  (закрытый enum); `value: null` ⇒ это честное состояние (`no_data`), не пустая строка;
  `resolution ∈ {original_kk, source_ru_shown_as_fallback, machine_translated}`. **Машинный перевод
  данных goszakup в MVP ЗАПРЕЩЁН** (это «выдуманное значение»). Сервер разрешает приоритет kk→ru
  (не фронт). `lang` обязан долетать до DOM как атрибут `lang="..."` (иначе скринридер озвучит
  неверно); видимый бейдж «рус. источник / орыс дереккөзі» при фолбэке.
- **Enum/булевы на проводе** — lower_snake строки (не int); tri-state явно (`{value:null,
  state:"no_data"}`, не `null` вперемешку с `false`). **Null** — отсутствие = `null` + честное
  состояние, НИКОГДА «0»/«—»/выдуманное.
- **Pagination** — keyset (offset на PostGIS деградирует): `?limit=<def 50,max 200>&cursor=<opaque>`;
  ответ `{items, page:{next_cursor, limit}}`; `total` только по `?with_total=true`.

### Communication Patterns

- **Outbox-события** — имя `<aggregate>.<event>` (lower-dot) из реестра `event_types`; конверт
  `{event_id (uuid), type, occurred_at, subject_ref, payload, v}`; `subject_ref` = URN
  `<entity>:<public_id>` (singular, `contract:44071234`); дедуп по `event_id`; версия payload — `v`.
- **Идемпотентность импорта** — дедуп-ключ `(source, goszakup_<entity>_id, snapshot_id)` UPSERT
  `ON CONFLICT DO UPDATE`; `import_run_id` UUID (трассировка), `snapshot_id` ДЕТЕРМИНИРОВАН (не
  random); повтор того же snapshot = no-op; outbox-вставка в той же транзакции.
- **Frontend state** — server-state TanStack Query (ключи-массивы `['contract', id]`); client-state
  минимум (тема/язык), иммутабельные апдейты.
- **Логирование (slog)** — структурное, ключи snake_case; обязательный контекст `import_run_id`,
  `snapshot_id`, `request_id`; уровни INFO/WARN/ERROR; НИКОГДА токены/`telegram_chat_id` в логах.

### Process Patterns

- **Пересчитываемость и нейтральность — структурой, не дисциплиной:**
  - Флаг — СТРУКТУРА (`{flag_id, methodology_version, evidence{все входы}, params_snapshot,
    severity}`), НЕ строка. Текст рождается только через `render(flag_id, evidence, params, locale)`
    из registry (нет API «написать предложение про флаг»).
  - Числа методики — из `methodology_params` (плейсхолдеры `{threshold}`); **числовые литералы в
    шаблонах флагов запрещены** (линтер registry).
  - «Недостаточно сопоставимых данных» рендерится ТОЛЬКО при `comparable_n < min_sample` (тот же
    порог, что в evidence); property-тест на однозначность (нельзя показать медиану при
    `insufficient`, и наоборот).
- **Error handling** — Go: ошибки вверх с `%w`, на HTTP-границе → `{error:{code,message}}`; паники
  → recover-middleware → 500 + лог. Frontend: error/loading TanStack Query; error boundary на маршрут.
- **Loading** — скелетоны под раскладку (карточки) / собственный лоадер карты, не спиннер-стена;
  карта прогрессивно (canvas → тайлы → объекты по bbox → кластеры → флаги).
- **Состояния компонента** — полный автомат `idle|loading|empty|partial|error|success` через
  обёртку `<DataState>` (`empty`=«нет данных» ≠ `partial`=«недостаточно сопоставимых»).
- **Validation** — zod (фронт: URL/внешнее) + `decode`+schema-hash (бэк); methodology_params
  иммутабельны.

### Frontend Consistency (рычаги против дрейфа)

- **Токены — 3 слоя:** primitive (приватные, в фичах ЗАПРЕЩЕНЫ) → semantic (используемые,
  **закрытый список-enum**: `--color-bg-surface`, `--color-fg-default/muted`, `--color-accent`,
  `--color-danger-fg`, `--focus-ring`…) → component (алиасы). Грамматика
  `--{category}-{role}-{variant?}-{state?}`, codegen валидирует. Тема — переопределение semantic
  в `[data-theme]` (фичи о теме не знают).
- **Lint как граница:** запрет хардкод-значений в CSS (stylelint), запрет сырых интерактивных
  элементов в фичах, запрет `outline:none` без замены, запрет сырого `toLocaleString`/конкатенации
  чисел/дат.
- **Обёртки-инкапсуляторы (одно место истины):** `shared/ui` примитивы (поверх Radix-механики),
  `<LangValue>` (все кейсы билингва + DOM `lang`), `<DataState>`, `<Icon name>` (один набор,
  типизированный закрытый `name`), `formatMoney`/`formatDate` (следуют языку chrome).
- **Карта** — палитра/глифы/состояния маркеров (обычный/выбранный/кластер/«есть сигнал») —
  закрытый enum через **JS-мост к semantic-токенам** (единственный UI вне CSS). `z-index` — шкала
  токенами (`--z-map/sticky/overlay/modal/toast`); брейкпоинты — токены + один хелпер.

### All-Surfaces Content Consistency (web / OG / Telegram)

**Один render-слой → три адаптера представления** (каналы НЕ переписывают смысл, источник прозы —
один registry). OG-картинка: рамка «сигнал, требующий проверки» в изображении + **обязательный
`og:image:alt`** (тот же текст словами) + `methodology_version`; честные состояния показывать явно
(не прятать несработавшие). Telegram: сокращение через registry short-форму (`flag.x.short`,
проходит тот же CT-тест) + deeplink на web, НЕ эвристика бота. **Cross-surface golden snapshot-тест:**
смысловое ядро (рамка, число, `flag_id`, `methodology_version`, locale) совпадает между web/OG/Telegram.

### registry/ — единый позвонок + перекрёстный тест

```
registry/
├── values/   honest_states(value_state+flag_state) · methodology_params(immutable) ·
│             glossary{key→kk,ru} · taboo_lexicon · event_types · error_codes{kk,ru,http_status}
└── rules/    case ^[a-z][a-z0-9_]*$ · api_path /<plural> · event <aggregate>.<event> ·
              version ^v\d+\.\d+$ · lang_suffix _(kk|ru)$  (НЕ _kz)
```
Направление генерации: **registry → (OpenAPI, sqlc-типы, i18n-скелет, token-имена)**; сгенерённое
не редактируется руками. **Перекрёстный тест на смыкание (~7 осей):** множества ключей
`value_state/flag_state` РАВНЫ в OpenAPI ∩ i18n.kk ∩ i18n.ru ∩ tokens ∩ glossary; `event_types`
== эмиттеры в коде; `error_codes` == возвращаемые == OpenAPI responses == i18n.kk ∩ i18n.ru;
`methodology_version` в evidence == текущая в params; константы прозы из params. **Сторожа:**
ноль taboo (нормализованный матчер: NFKC + гомоглифы + падежи + kk-морфология); ноль `kz`-как-языка;
**рождение** (имя вне registry = fail — защищает будущее); **генерация** (`generated == regenerated`).
**i18n-ключи разведены:** значения (в тесте) vs UI-строки (вне теста).

### Enforcement Guidelines

**Все AI-агенты ОБЯЗАНЫ:** пользовательские строки — через i18n из registry (KZ+RU); доменные
данные — с пометкой языка (DOM `lang`); никаких хардкод-строк/чисел/цветов; различать
`no_data`≠`insufficient_sample`≠`not_comparable`; имена/enum/события/коды/токены — из registry
(сторож рождения); не выдумывать значения/координаты; флаг — структура, текст — из шаблона +
обязательная рамка-токен.
**Enforcement (CI, красный = блок merge):** `go vet`/`gofmt`/`golangci-lint`; `eslint`/`prettier`/
`stylelint`/`tsc`; doc-нейтральность (двунаправленный матчер); перекрёстный registry-тест (~7 осей
+ 4 сторожа); contract+schema-hash; property-тест «недостаточно данных»; cross-surface snapshot.

### Pattern Examples

| Делать | Анти-паттерн |

### Architectural Boundaries (исполняемые, не нарисованные)

- **API:** один публичный read-only `/api/*` (chi, без auth); `importer`/`stage0` — без публичной
  поверхности; `bot` — polling (без публичного эндпоинта); Directus — внутренняя админка. Токен
  goszakup только у `importer`.
- **Исполняемые границы (CI go-list-тест):** `goszakup` импортируется ТОЛЬКО из `ingest/decode`;
  `flags/median/normalize/benchmark` НЕ импортируют `store`/`httpapi`/`goszakup`/реальное время
  (чистота = пересчитываемость без БД); `og`/`bot` берут прозу ТОЛЬКО через `render` (нейтральность
  — одна точка контроля).
- **Данные:** ПРОЕКЦИОННЫЕ (`0002`, derived из снапшота) ⊥ КУРАТОРСКИЕ (`0003`, ручные правки) —
  разные гранты И раздельные `store/projection` vs `store/curation` (граница в Go, не только в БД);
  `registry` — источник имён/значений (рантайм-чтение); снапшот лёгкий (`ingest` дамп +
  `store` projection-мета).
- **Компоненты (фронт):** фичи компонуют из `shared/ui` (никаких сырых интерактивных элементов);
  `shared` без домена; токены/i18n/состояния — через обёртки.

### registry: рантайм-чтение + 2 генератора + валидирующий тест

`registry/values` ЧИТАЕТСЯ В РАНТАЙМЕ (methodology_params/lexicon/glossary/honest_states/
error_codes — JSON/YAML, `methodology_version` запрашиваем из `/api`; лучше для пересчитываемости,
без пятничного codegen-краша). **Генераторы только два:** `openapi-typescript` (TS-типы из
openapi.yaml) и `tokens-codegen` (tokens.json → CSS-переменные). **Перекрёстный тест ВАЛИДИРУЕТ
смыкание** (~7 осей: value_state/flag_state равны в OpenAPI ∩ i18n.kk ∩ i18n.ru ∩ tokens ∩
glossary; event_types == эмиттеры; error_codes == возвращаемые == OpenAPI == i18n; version в
evidence == params; константы прозы из params) **+ сторожа** (ноль taboo нормализованным матчером;
ноль `kz`-как-языка; рождение имени вне registry = fail; `generated==regenerated`), НЕ генерируя
остальное.

### Integration Points

- **Внутренние:** `outbox` (importer пишет ↔ bot читает); `ingest/decode`+schema_hash (ows_v2↔домен);
  registry рантайм-чтение + 2 генератора; `snapshot_id` сквозь импорт→флаги→evidence→OG.
- **Внешние:** ows_v2 (токен, `importer`); Telegram (bot, polling, через outbox); Nominatim (batch,
  эфемерно, профиль `geocode`); PMTiles (статика Caddy); managed-геокодер — fallback.
- **Поток данных:** `/v2/journal` → `ingest/decode`(schema_hash) → проекц. таблицы (UPSERT idem,
  ключ `(source,goszakup_id,snapshot_id)`) → `normalize` → `flags`/`median`(чистые) → `benchmark`
  swap → `outbox` → `bot`; параллельно `geo`(Nominatim batch) → `geo_objects`(кураторские); выдача:
  `api` ← read-модели → `web`/`og`. Лексикон нормализации грузится `importer`-командой (loader),
  НЕ миграцией.

### Development Workflow

- **Dev:** `docker compose up` (горячий на синтетике, S-0); `--profile geocode` (Nominatim batch);
  `--profile cold` (importer/directus/bot).
- **Codegen:** `make gen` = `gen-sqlc` + `gen-web` + `gen-tokens` (версии запинены; сгенерённое
  закоммичено; `generated==regenerated` в CI на объединении путей). В S-0 — только sqlc + web.
- **Тесты:** unit/property co-located; integration под `//go:build integration` (не в обычном
  `go test ./...`); `fixtures.go` (embed) делит фикстуры с Playwright (`@fixtures`); golden — сырой
  JSON от одного генератора; cross-surface (web/OG/Telegram) против `fixtures/golden/cross_surface`.
- **Build/Deploy:** GitHub Actions (path-фильтры; `fixtures/**` триггерит оба) → образы → один VPS
  (РК), Caddy авто-TLS; **бэкап ТОЛЬКО Postgres** (Nominatim/PMTiles воспроизводимы из `tools/`);
  назначен один владелец инфры; disk-бюджет в `docs/ops/runbook.md`.

1. **Идемпотентность и атомарность импорта (было критическим, специфицировано):**

2. **Состояние контейнера/района (третья ось честности):** `container_state` для района/списка —
   `no_contracts` / `no_flags_raised` / `not_geocoded` (различимы), видимо отдельной строкой в
