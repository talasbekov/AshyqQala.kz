# Story 6.1: Фильтрация контрактов

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a Данияр-журналист,
I want фильтровать список контрактов по фасетам (направление / период / сумма / наличие флага / подрядчик),
so that я быстро сужаю выборку до аномалий и проваливаюсь в первоисточник.

Реализует **FR-15** (UC-04, UJ-3). Эпик 6 несёт **NFR-1** (поиск/карточка <1с p95) и **UX-DR16/34**.

## Acceptance Criteria

Источник: `epics.md#Story-6.1` (BDD), `prd.md#FR-15`, `EXPERIENCE.md` (filter-chip, пустой результат).

**AC1 — Немедленное применение фасетов**
**Given** фасеты `направление / период / сумма / наличие флага / подрядчик`
**When** пользователь тапает чип `{filter-chip}`
**Then** применение **немедленное** (без кнопки «Применить»); список пересобирается; повторный тап по чипу снимает его; комбинации фасетов работают **совместно** (AND между типами фасетов; OR внутри одного фасета — напр. направление road+water).

**AC2 — Выбранное состояние чипа (не-цветовой признак, WCAG 1.4.1)**
**Given** выбранный чип
**When** он отрисован
**Then** насыщённая заливка `{colors.link-on-sunken}` (#0C6585, светлая тема; dark — авто-свап через `aq.dark`) + белый текст `{colors.on-primary}` (контраст ≥4.5:1) + **галочка «✓» перед текстом** (глиф из `Icon` `verified`) + bold; хитбокс ≥`{spacing.tap-target}` (44px); виден `{components.focus-ring}`. Невыбранный — `{colors.surface-sunken}` + `{colors.text-secondary}` + бордюр `{colors.border}`.

**AC3 — Пустой результат (честность, без выдумывания)**
**Given** фильтры слишком узкие → 0 результатов
**When** список пуст
**Then** показывается «Ничего не найдено» + предложение **расширить фильтр** (RU «Попробуйте расширить фильтр» / KZ «Сүзгіні кеңейтіп көріңіз») с быстрым сбросом одного-двух чипов; **никаких выдуманных результатов**. Бэкенд при пустой выборке отдаёт `[]` (НЕ `null`).

**AC4 — «период» — это фасет поиска, НЕ окно медианы**
**Given** UI-фильтр «период» (напр. 12 мес)
**When** он применён
**Then** он сужает выборку контрактов по `sign_date`; он **НЕ** меняет окно медианы (медиана всегда скользящие 24 мес — см. `4-1`/`4-3`/`6-4`). Граница между «фасетом периода» и «окном медианы» зафиксирована тестом/комментарием.

**AC5 — Бэкенд: фасетный list-эндпоинт + keyset-пагинация**
**Given** новый `GET /api/contracts` с query-параметрами (snake_case)
**When** заданы фасеты
**Then** возвращается отфильтрованный список контракт-айтемов (wire snake_case, деньги строкой, честный конверт там, где nullable), детерминированный порядок `sign_date DESC NULLS LAST, goszakup_contract_id`, keyset-пагинация; ответ проходит kin-openapi-валидацию против `openapi.yaml`; `is_deleted` скрыты.

**AC6 — Нейтральность фасета «наличие флага»**
**Given** фасет/маркер «наличие флага» в списке
**When** он подписан и отрисован
**Then** формулировка нейтральна — «сигнал, требующий проверки» (НЕ «нарушение»/«коррупция»); проходит lexicon-страж нейтральности (ноль taboo-токенов) — наследует контракт нейтральности Epic 4/5.

#### Референс-сниппет SQL (стартовая точка — проверь синтаксис sqlc 1.31, отшлифуй keyset)

```sql
-- name: ListContracts :many
-- Фасетная фильтрация контрактов (FR-15). Условные фасеты: narg IS NULL ⇒ фасет не задан.
SELECT
    c.goszakup_contract_id, c.subject_ru, c.subject_kk, c.amount_tng,
    c.sign_date, c.status, c.direction, c.kato_code,
    EXISTS (SELECT 1 FROM risk_flags rf WHERE rf.contract_id = c.id AND rf.is_active) AS has_active_flag
FROM contracts c
WHERE NOT c.is_deleted
  AND (sqlc.narg('directions')::text[] IS NULL OR c.direction = ANY(sqlc.narg('directions')))
  AND (sqlc.narg('signed_from')::date  IS NULL OR c.sign_date  >= sqlc.narg('signed_from'))
  AND (sqlc.narg('signed_to')::date    IS NULL OR c.sign_date  <= sqlc.narg('signed_to'))
  AND (sqlc.narg('amount_min')::bigint IS NULL OR c.amount_tng >= sqlc.narg('amount_min'))
  AND (sqlc.narg('amount_max')::bigint IS NULL OR c.amount_tng <= sqlc.narg('amount_max'))
  AND (sqlc.narg('supplier_org_id')::bigint IS NULL OR c.supplier_org_id = sqlc.narg('supplier_org_id'))
  AND (NOT sqlc.arg('has_flag_only')::bool OR EXISTS (
        SELECT 1 FROM risk_flags rf WHERE rf.contract_id = c.id AND rf.is_active))
ORDER BY c.sign_date DESC NULLS LAST, c.goszakup_contract_id
LIMIT sqlc.arg('lim');
```

> **Keyset-пагинация:** курсор = `(sign_date, goszakup_contract_id)` последней строки. При `DESC NULLS LAST` предикат продолжения нетривиален (NULL `sign_date` идёт последним) — закодируй детерминированно (напр. отдельная ветка для «уже в хвосте NULL»). Документировано как convention: `httpapi/doc.go:1`, `architecture.md:730`. Размер страницы держи щедрым (пилот Астаны — объём по OQ-1 ещё открыт), чтобы типовой запрос укладывался в одну страницу.
