## Story

**Как** гражданин,
**Я хочу** поделиться карточкой контракта с корректным нейтральным превью,
**Чтобы** ссылка в мессенджере/соцсети выглядела правдиво и проверяемо.

Контекст: шаринг (FR-27, UC-07, реализует UJ-1) — **свойство публичной страницы**, развязанное с gate-ом
нейтральности (gate стоит на сервере в момент публикации флага; OG — рендер уже-gated источника, **не второй
страж**). Это последняя «дверь наружу» полной проверяемой картины Эпика 5: пересланный скриншот карточки
должен переживать пересылку и оставаться проверяемым (видимый короткий URL/QR + версия методики запекаются в
картинку). Валидирует **SM-5** (3+ публикации СМИ со ссылкой на платформу).
[Source: epics.md#Epic 5 → Story 5.5; prd.md §5.10 FR-27; architecture.md:48, 140–143; prd.md#metrics SM-5]

## Acceptance Criteria (дословно из эпика, lines 1604–1614)

### AC-1 — Серверная отдача OG-тегов из той же проекции, что и SPA (FR-27)
**Given** серверный OG-рендер Go из ТОЙ ЖЕ проекции, что и SPA (FR-27)
**When** ссылка шарится
**Then** OG-теги (заголовок, сумма, превью) отдаёт **сервер (не клиентский JS)**; цифры **не расходятся с SPA**.

Тестируемо:
- OG-`<meta>`-теги присутствуют в **серверном** HTML-ответе (не инъекция клиентским JS — краулеры соцсетей JS не исполняют). Минимальный контракт FR-27: `og:title` (заголовок), сумма, `og:image` (превью). [prd.md FR-27 «Consequences»: «Карточка отдаёт OG-теги: заголовок, сумма, превью»]
- Цифры (сумма ₸, состояния/число флагов) берутся из **того же `ContractDTO`-пути**, что кормит SPA, и **совпадают** с тем, что показывает SPA («цифры не должны разойтись» — architecture.md:301, 439). Доказывается cross-surface golden-снапшотом (см. AC-4 / T7).
- Сумма форматируется как у SPA (`240 000 000 ₸`, группировка + `₸`, по локали), но **серверным** форматтером (Go не имеет `Intl` — см. NEW#3).

### AC-2 — OG-превью с флагом: нейтральная рамка, alt, версия, защитные связи, язык
**Given** OG-превью с флагом
**When** оно рендерится
**Then** рамка «**сигнал, требующий проверки**» + **обязательный** `og:image:alt` + `methodology_version`; ссылки на **первоисточник** и **методику**; упоминание «**Сообщить об ошибке**»; **язык — выбранный**.

Тестируемо (UX-DR36 + UX-DR28 + AR-14 + §7.1/§7.4):
- Нейтральная рамка-токен «сигнал, требующий проверки» / «тексеруді талап ететін сигнал» — **и в изображении (словами), и в `og:image:alt`** (тот же текст словами). Никогда не алый, никогда «нарушение/коррупция/виновен» (RU) / «бұзушылық/сыбайлас жемқорлық/кінәлі» (KZ). [epics.md:408–410 UX-DR36; :373–376 UX-DR27; prd.md:311–312 §7.1]
- `og:image:alt` **обязателен** (architecture.md:628–629 All-Surfaces — «обязательный `og:image:alt`»).
- `methodology_version` присутствует в тегах **И** запечён видимо на картинке (с коротким URL/QR — скриншот переживает пересылку). [architecture.md:142–143 AR-14]
- **Достижимость защитных связей (UX-DR28, жёсткий gate):** на OG рядом доступны (а) путь к методике/пересчёту и (б) канал «Сообщить об ошибке». **Без сопровождающего пути флаг НЕ публикуется ни на одной поверхности** — включая OG. [epics.md:377–379 UX-DR28]
- Рабочая ссылка на первоисточник (goszakup, FR-11) и на экран методики (FR-23 / методика 5.3). Упоминание канала «Сообщить об ошибке» (FR-28; deep-link `?report` — конвенция из 5.4).
- **Язык — выбранный**, резолвится **на сервере из URL/cookie** (localStorage серверу недоступен — epics.md:351 UX-DR21 «localStorage + URL/cookie для серверного OG»); **дефолт — казахский** (NFR-6).
- **Честные состояния явно** (§7.4): отсутствующее поле → «нет данных», не «0»; несработавший/недостаточный флаг → «недостаточно сопоставимых данных»; **не прятать несработавшие** (architecture.md:629). Карточка без активных сигналов — честно «нет активных сигналов», не пустая «чистая».

### AC-3 — Версионирование OG-картинки по methodology_version (+as_of) → cache-bust (AR-20)
**Given** смена методики (AR-20)
**When** версия изменилась
**Then** URL OG-картинки **версионируется** по `methodology_version` (+`as_of`) → **cache-bust** при смене методики.

Тестируемо (AR-20, architecture.md:888–889):
- URL OG-картинки содержит `methodology_version` (+`as_of`); при смене версии URL меняется → старое превью в кэшах соцсетей инвалидируется.
- Пустая/отсутствующая `methodology_version` **не** попадает в URL как пустая «ok»-строка — деградирует в честное состояние (анти-паттерн «honesty hole» 5.1, см. Lessons A).

### AC-4 — (signature deliverable) Cross-surface golden snapshot web↔OG + per-surface нейтральность OG
> Это AC выводится из обязательств Эпика 5 («per-surface рендер-тест нейтральности web/OG», epics.md:531)
> и из явно отложенного на 5.5 в `deferred-work.md:43`. Готовит вход для Story 5.7.

**Given** OG как вторая публичная поверхность (первая — web)
**When** web и OG рендерят золотой текст флага
**Then** OG проходит **per-surface нейтральность-тест** (ноль taboo в обеих локалях, рамка-токен присутствует) **И** cross-surface golden-снапшот подтверждает совпадение смыслового ядра `{рамка, число, flag_id, methodology_version, locale}` между web и OG. [architecture.md:631–632; epics.md:1648–1650 Story 5.7]

Тестируемо:
- Per-surface OG нейтральность: `registry.FindTaboo` по **каждой** генерируемой OG-строке (title/description/текст картинки) × обе локали × все 4 состояния флага = 0 совпадений (зеркало `render_test.go:178`).
- Cross-surface golden: смысловое ядро `{frame, число, flag_id, methodology_version, locale}` идентично между web и OG; golden запинен **литералом**, включает кейсы `raised / not_raised / insufficient_data` (не только happy-path).
- **Стражи обязаны доказать, что краснеют** ([[guards-must-prove-red]]): negative-control + `-count=1` + golden-литерал (см. Lessons B).
