# Story 4.4: Флаг «монополия в регионе» (FR-21)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **система AshyqQala.kz (compute-ядро)**,
I want **помечать нейтральным флагом Подрядчика (БИН), когда его доля по сумме ₸ в группе (КАТО × направление) ≥ `concentration_share` (0.5) при достаточном числе контрактов в группе — по пересчитываемой методике, с полным `evidence`**,
so that **журналист/гражданин видит концентрацию-доминирование как сигнал к проверке (UJ-3), а при малой выборке (`< min_group_contracts`) или неразрешённом БИН честно НЕ строится флаг («недостаточно сопоставимых данных»/«профиль уточняется»), а не выдуманная монополия**.

> **Тип истории:** флаг-история Эпика 4 (compute, **backend-only**). Реализует FR-21 поверх benchmark-группировки Story 4.1 + `risk_flags`/`RiskFlagStore` Story 4.2 (+ рефактор 4.3). **Гардрейл эпика:** выход НЕ виден пользователю и НЕ «опубликованный флаг» — приёмка на ДАННЫЕ. [Source: epics.md:1445-1463, 1594; prd.md#FR-21:240-241]
>
> **⚠️ Sprint Change (прецедент 4.1/4.2/4.3):** Epic 4 «🚫 ожидает токен» (`epics.md:1385-1387`: суммы FR-21 — живой ows_v2 `/v2/contract`). По решению владельца (2026-06-24, [[sprint-sequencing-epic1-first]]) флаги строятся на СИНТЕТИКЕ + честный дескоуп живых данных. 4.4 строит ЧИСТУЮ логику флага монополии + evidence + интеграцию с `risk_flags` (contractor-субъект) на синтетических групповых агрегатах; ЖИВЫЕ суммы (`/v2/contract`, Epic 2) и **живая нормализация БИН** (`org_name_aliases.resolve_status`, Epic 2 Story 2.3) — ДЕСКОУП.

> **🔑 ГЛАВНОЕ ОТЛИЧИЕ от 4.2/4.3 — НЕ клонировать contract-путь:** монополия — это (а) флаг на **Подрядчика** (`subject_type='contractor'`, `organization_id`), НЕ на контракт; (б) **групповой агрегат** (доля топ-БИН по сумме ₸ в группе), НЕ функция одного контракта; (в) **гейтится статусом нормализации** БИН (manual/conflict → НЕ флагать). Реюз 4.2/4.3 — паттерн транзакции/идемпотентности и чистая-функция-форма, НО субъект и запросы — новые (contractor).

## Acceptance Criteria

**AC1 — Чистый флаг monopoly: `(group-inputs, params) → (FlagState, evidence)`; порог из methodology_params**
**Given** ЧИСТЫЙ пакет `internal/flags` + `methodology_params.flag.monopoly.{concentration_share=0.5, min_group_contracts=5}` (уже в `flags.Params` со Story 4.1, валидируется в `methodology.Load`) + входы группы (КАТО × направление): сумма ₸ топ-БИН, сумма ₸ всей группы (знаменатель), число контрактов в группе, статус разрешённости топ-БИН (resolved bool), ключ группы
**When** число контрактов группы ≥ `min_group_contracts`, знаменатель > 0, топ-БИН разрешён, и доля топ-БИН (`supplier_sum / group_total`) ≥ `concentration_share`
**Then** возвращается `registry.FlagRaised`; `evidence` (структура) хранит ВСЕ входы: `bin`, `supplier_sum`, `group_total_sum`, `group_contracts`, `share` (или numer/denom), `concentration_share`, `min_group_contracts`, `comparability_key` (direction×kato), `methodology_version`; порог берётся ТОЛЬКО из params (литералов 0.5/5 нет); пакет `flags` остаётся ЧИСТЫМ (`make check-core` зелёный).
[Source: prd.md#FR-21:240-241; epics.md:1453-1455; data-model §2:79-80; architecture.md:591-592, 596-598, 775-776]

**AC2 — Честные состояния: малая выборка / неразрешённый БИН / нулевой знаменатель → флаг НЕ строится**
**Given** идемпотентный пересчёт
**When** число контрактов группы `< min_group_contracts` (выборка мала) ИЛИ знаменатель `group_total_sum ≤ 0` (база недостоверна) → `FlagInsufficientData` («недостаточно сопоставимых данных»); статус нормализации топ-БИН `manual`/`conflict` (НЕ resolved) → флаг по этому БИН НЕ строится («профиль уточняется», НЕ выдуманная монополия); доля < `concentration_share` → `FlagNotRaised`
**Then** однозначность: `raised` ⟺ (контрактов ≥ min, знаменатель > 0, БИН разрешён, доля ≥ share). Property-тест; никаких монополий «из воздуха».
[Source: prd.md#FR-21:241, §7.4; prd.md:185 (manual/conflict не основание флага); epics.md:1457-1463; CLAUDE.md «honesty over inference»; **урок ревью 4.3: непозитивный знаменатель → insufficient, не фабрикация**]

**AC3 — Детерминированное сравнение доли с порогом (целочисленно-рациональное, без float; ≥ инклюзивно)**
**Given** деньги — целые ₸ (Q3 Story 4.1), доля порога — дробная (0.5)
**When** считается «доля ≥ concentration_share»
**Then** сравнение ДЕТЕРМИНИРОВАНО и пересчитываемо вручную: `supplier_sum × denom ≥ group_total × numer`, где `concentration_share = numer/denom` (для 0.5 → `supplier_sum × 2 ≥ group_total × 1`); БЕЗ плавающего деления в сравнении; **граница ровно ==share → raised (инклюзивное ≥, в отличие от строгого > в 4.3 — FR-21 «≥»)**; тот же вход + та же `methodology_version` → тот же результат бит-в-бит.
[Source: epics.md:1454 («≥»); architecture.md:298, 557-558, 736 (детерминизм/целые ₸); prd.md#FR-23; **прецедент Q1 Story 4.3 (рациональное целочисленное)**]

**AC4 — Интеграция с risk_flags по CONTRACTOR-субъекту + порядок; живые суммы/нормализация — дескоуп**
**Given** таблица `risk_flags` (Story 4.2, миграция 0007 — УЖЕ поддерживает `subject_type='contractor'`, `organization_id`, частичный uniq `risk_flags_org_uniq (flag_type, organization_id)`, CHECK-и) + `recalc.Run` (Story 4.1)
**When** пересчёт флагов
**Then** флаг monopoly идемпотентно публикуется/снимается в `risk_flags` по **organization_id** (`flag_type='monopoly'`, `subject_type='contractor'`); используются НОВЫЕ sqlc-запросы org-субъекта (`RaiseContractorFlag`/`ClearContractorFlag`/`GetContractorFlag`/`CountActiveContractorFlags`, `ON CONFLICT (flag_type, organization_id)`); подключён как `recalc.FlagRecalculator` (после benchmark swap, как 4.2/4.3); ЖИВЫЕ суммы (`/v2/contract`) и нормализация (`org_name_aliases`) — ДЕСКОУП (на синтетике групповые агрегаты + resolved-флаг из golden/Provider). Критерий закрытия AC4 = «contractor-recalculator подключён + idempotent org-flags + тест на синтетике + источники задокументированы для Epic 2».
[Source: epics.md:1455, 1405-1407; migrations/0007_risk_flags.sql (org_uniq, subject_chk='contractor'); architecture.md:880-881; data-model §E; Story 4.2/4.3 (risk_flags/RiskFlagStore)]

**AC5 — Пересчитываемость и гардрейлы (несущие)**
**Given** гардрейлы платформы
**When** флаг принимается
**Then** (а) пороги — ТОЛЬКО из methodology_params (литералов 0.5/5 нет); (б) `methodology_version` в evidence == в params; (в) приёмка на ДАННЫЕ (Go/SQL), не на экран; (г) НЕЙТРАЛЬНОСТЬ (флаг — «сигнал, требующий проверки», через render; нет taboo); (д) честность: insufficient ⟺ контрактов<min или знаменатель≤0; неразрешённый БИН → не строится; (е) формула намеренно простая (доля по сумме, НЕ HHI/Джини) — публичная объяснимость.
[Source: prd.md#FR-21, FR-23, §7.1/§7.4; architecture.md:591-592, 596-598, 647; data-model §2:79-80; epics.md:1594; **delta-семантика провайдера — решение владельца 2026-06-25**]
