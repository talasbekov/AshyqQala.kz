## Challenges / рекуррентные паттерны (системные уроки) — *подтверждены Project Lead*

1. **int64-overflow в пороговой арифметике флагов** — `price×1000` (4.3:56), `supplier×1000` (4.4:222). Один класс дважды → систематика. Недостижимо в домене, но **граница живого импорта (Epic 2) обязана** ввести overflow-guard на суммы BIGINT.
2. **scale-усечение факторов методики** — `factorScale=1000` (4.3), `shareScale=1000` (4.4): >3 знаков после запятой молча усекаются; комментарий «бит-в-бит» переоценивает детерминизм. При вводе НЕ-дефолтного порога — валидировать `factor×scale` целым в `methodology.Load`.
3. **store схлопывает честные состояния** — insufficient/not_raised (4.2), not_published/insufficient (4.5). Backend хранит только активные флаги → **Epic 5 обязан реконструировать состояния на чтении** из доступности evidence (иначе «нет данных» неотличимо от «проверено, сигнала нет» — удар по гардрейлу честности).
4. **delta-семантика провайдера** (4.2/4.3/4.4) — эскалирована до решения владельца 2026-06-25: провайдер передаёт каждый контракт, чьё состояние мог измениться; снятие по отсутствию — Epic 2 (живой источник). Инвариант «полный набор / без дублей субъекта» зафиксирован для Epic 2.
5. **Дисциплина стражей — апгрейд (главный системный, продолжение Epic 1 retro #1):** negative-control обязан доказывать **ПРИЧИНУ** покраснения (подстрока ошибки / конкретный обойдённый кейс), а не факт `err != nil`. 4.5 (loader) и 4.6 (линтер `{1.5}`) показали оба режима. *(подтверждено Project Lead)*
6. **Крупный uncommitted-объём — повторный риск (боль).** Весь Эпик 4 (4.1–4.6) + ревью-фиксы 4.6 — некоммитнуты на ветке `story/0-1-stage0-access`. В Epic 1 это был action item (закоммитили Эпик 1); для Эпика 4 копили. *(подтверждено Project Lead как боль; критпуть фиксации)*
