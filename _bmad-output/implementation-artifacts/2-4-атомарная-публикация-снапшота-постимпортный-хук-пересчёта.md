# Story 2.4: Атомарная публикация снапшота + постимпортный хук пересчёта

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **гражданин**,
I want **всегда видеть целостный снапшот данных**,
so that **мне никогда не показывают полупересчитанное состояние** (флаги/медианы не строятся против устаревших или наполовину пересчитанных данных).

## Acceptance Criteria

> Дословно из эпика [Source: _bmad-output/planning-artifacts/epics.md#Story 2.4 (строки 1138-1158)]. Уточнения помечены *(уточнение 2.4)* и обязательны к выполнению.

**AC1 — зафиксированный постимпортный порядок + типизированный хук + тест «ровно 1 раз»**
- **Given** завершённый импорт **When** запускается постимпортный конвейер **Then** порядок зафиксирован: **импорт → нормализация (FR-2) → хук пересчёта (benchmark swap → флаги) → атомарная публикация снапшота**; хук — типизированный интерфейс `RecalcHook` с дефолтом `noopRecalc`.
- **And** тест проверяет, что `RecalcHook` вызван **РОВНО 1 раз** на публикацию снапшота; шов компилируется и наблюдаем **без реального потребителя** (анти-фиктивность, Amelia).
- *(уточнение 2.4)* `RecalcHook` — это тонкий именованный шов поверх уже существующего `recalc.Run`; реальный потребитель = `recalc.Run(ctx, benchmarkRecalculator, flagsRecalculator)`. `noopRecalc` — вызываемый no-op (НЕ `nil`), с compile-time `var _ RecalcHook = noopRecalc{}`.

**AC2 — читатель видит снапшот целиком**
- **Given** читатель во время пересчёта **When** запрашивает данные **Then** видит снапшот целиком (старый ИЛИ новый), **не полупересчёт** (атомарный swap).
- *(уточнение 2.4)* пересчёт одного прогона обязан читать медианы из **одного снапшота** (закрыть долг «median reads outside flag-write tx», см. Dev Notes §5) и пинить **один `clock.Now()`** на весь проход — иначе один пересчёт смешает старые и новые медианы / пересечёт границу суток.

**AC3 — атомарный swap проекции без даунтайма**
- **Given** проекционная таблица read-моделей **When** пересчёт «в сторону» завершён **Then** атомарный swap заменяет активную проекцию **без даунтайма** (по образцу `BenchmarkStore.ReplaceSnapshot`: `DELETE all + INSERT` в одной `pgx.Tx` → commit; читатель по MVCC видит целое).
- *(уточнение 2.4)* шаг нормализации (первый постимпортный) обязан применяться **атомарно** — закрыть долг «`orgnorm.Apply` нетранзакционен» (см. Dev Notes §5.1).

**Гардрейл честности (обязателен):** при отсутствии входов (например, нет `geo_objects.length_km` из Epic 3) публиковать **пустой/insufficient снапшот честно**, НЕ фабриковать медианы. Атомарный swap НИКОГДА не должен обнажать полупересчитанную проекцию, которую читатель воспримет как «проверено, сигнала нет». [Source: CLAUDE.md#Two load-bearing guardrails; _bmad-output/implementation-artifacts/4-1-…md:215]

### §6. Снапшот/миграции — решение по скоупу

Атомарность «читатель видит целое» обеспечивается **транзакционным per-table swap (MVCC)**, который УЖЕ существует (`ReplaceSnapshot`, `applyFlagOutcomes`). **Глобальной таблицы-указателя/версии снапшота НЕТ и она НЕ требуется** для AC2/AC3 в MVP. Поэтому **2.4 вероятно НЕ требует новой миграции**. Лёгкий `snapshot_id`-штамп (AR-5) — опционален и может быть отложен (он нужен evidence-воспроизводимости Epic 4/5, не атомарности). Если dev всё же вводит снапшот-мету/указатель — следующий свободный номер миграции `0015` (goose `-- +goose Up/Down`, последняя существующая `0014_contracts_org_fk.sql`). НЕ вводить Redis/event-sourcing. [Source: миграции `migrations/0001..0014`; architecture.md#store (projection_snapshot-мета концептуально в `store/geo.go`, физически не создана)]
