## Story

As a **команда**,
I want **доказать, что ре-импорт не плодит дублей и не съедает ручной труд**,
so that **курируемые правки переживают ежедневный импорт** (S-0-приёмка пересчитываемости и доверия к данным).

## Acceptance Criteria

**AC1 — инвариант идемпотентности + выживания курации (S-0)**
- **Given** граница ПРОЕКЦИОННЫЕ ⊥ КУРАТОРСКИЕ таблицы **с раздельными грантами** (importer без write к курируемым; Directus без write к проекционным) и раздельные `store/projection` vs `store/curation`
- **When** выполнен сценарий `импорт → курация(строка R) → импорт`
- **Then** `assert`: правка R цела ∧ дублей нет ∧ медианы **БИТ-в-БИТ идентичны (ε = 0)** для того же снапшота — детерминизм через инъекцию `Clock` (НЕ «примерно стабильны»: одинаковый снапшот → одинаковый результат по контракту пересчитываемости).

**AC2 — CI-гейт (страж, не ручной прогон)**
- **Given** этот инвариант **When** открыт PR, трогающий импорт или нормализацию **Then** property/integration-тест гоняется в CI day-1 (**красный = блок merge**), а не только ручной S-0-прогон.
- *(уточнение 2.6)* эпик называет «testcontainers (`postgis/postgis`)», но репо использует конвенцию `//go:build integration` + `DATABASE_URL` + `t.Skip` (testcontainers НЕ в `go.mod`) — следовать конвенции репо; CI поднимает `postgis/postgis` как сервис (см. Вопросы владельцу).

**AC3 *(уточнение 2.6, вобрано из code-review 2.4 2026-06-29)* — реальный enforcement одиночности постимпортного джоба**
- **Given** `pipeline.RunPostImport` декларирует «единственный джоб, не запускать конкурентно» только КОММЕНТАРИЕМ (нет `pg_advisory_lock`) — долг из ревью 2.4
- **When** два постимпортных джоба пытаются идти одновременно
- **Then** одиночность ENFORCED через `pg_advisory_lock` (второй джоб ждёт ИЛИ честно отказывается), с краснеющим integration-тестом конкуренции. [Source: deferred-work.md#Deferred from: code review of story-2.4]

**Гардрейл честности:** «БИТ-в-БИТ медианы» сейчас тривиально пусты (нет `geo_objects.length_km` до Epic 3 → `price_benchmarks` пуст).
