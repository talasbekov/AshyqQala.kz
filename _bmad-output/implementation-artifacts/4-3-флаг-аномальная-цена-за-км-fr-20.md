# Story 4.3: Флаг «аномальная цена за км» (FR-20)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **система AshyqQala.kz (compute-ядро)**,
I want **помечать контракт нейтральным флагом, когда цена за км превышает медиану сопоставимой группы более чем в `deviation_factor` (1.5) раза — по пересчитываемой методике, с полным `evidence`**,
so that **журналист/гражданин видит ценовую аномалию как сигнал к проверке (UJ-3), а при недостаточной выборке или отсутствии длины дороги честно показывается «недостаточно сопоставимых данных», а не выдуманная аномалия**.

> **Тип истории:** флаг-история Эпика 4 (compute, **backend-only**). Реализует FR-20 поверх benchmark-движка Story 4.1 + `risk_flags`/`RiskFlagStore` Story 4.2. **Гардрейл эпика:** выход НЕ виден пользователю и НЕ «опубликованный флаг» — приёмка на ДАННЫЕ. [Source: epics.md:1383, 1594; prd.md#FR-20]
>
> **⚠️ Sprint Change (прецедент 4.1/4.2):** Epic 4 «🚫 ожидает токен» (`epics.md:1385`: суммы FR-20 — живой ows_v2). По решению владельца (2026-06-24, [[sprint-sequencing-epic1-first]]) флаги строятся на СИНТЕТИКЕ + честный дескоуп живых данных. 4.3 строит ЧИСТУЮ логику флага цены + evidence + интеграцию с `risk_flags` на синтетических ценах/медианах; ЖИВЫЕ суммы (`/v2/contract`, Epic 2) и **`geo_objects.length_km`** (Epic 3, отсутствует) — ДЕСКОУП. Без длины дороги цена/км НЕ вычислима → флаг честно НЕ строится (это прямо AC3 ниже, не баг).

## Acceptance Criteria

**AC1 — Чистый флаг price_per_km: `(inputs, params) → (FlagState, evidence)`; порог из methodology_params**
**Given** ЧИСТЫЙ пакет `internal/flags` + `methodology_params.flag.price_per_km.deviation_factor` (1.5, уже в `flags.Params` со Story 4.1) + входы: цена/км контракта (`*int64`, nil = не вычислима, напр. нет длины), медиана группы (`*int64`, nil = недостаточно), `sample_size`
**When** цена/км и медиана доступны, `sample_size ≥ median.MinSample`, и цена/км > медиана × `deviation_factor`
**Then** возвращается `registry.FlagRaised`; `evidence` (структура) хранит ВСЕ входы: `price_per_km`, `median`, `sample_size`, `deviation_factor`, `comparability_key` (direction×kato), `methodology_version`; порог берётся ТОЛЬКО из params (литералов нет); пакет `flags` остаётся ЧИСТЫМ (`make check-core` зелёный).
[Source: prd.md#FR-20:236; epics.md:1433-1435; architecture.md:591-592, 596-598, 775-776; data-model §2:78]

**AC2 — Честные состояния: недостаточная выборка / нет длины → флаг НЕ строится**
**Given** идемпотентный пересчёт
**When** выборка группы `< median.MinSample` (медиана недостоверна) ИЛИ медиана отсутствует → `FlagInsufficientData` («недостаточно сопоставимых данных»); цена/км не вычислима (для дороги нет `length_km`) → флаг НЕ строится (`insufficient_data`/`not_comparable`, НЕ выдуманная аномалия); цена/км ≤ порога → `FlagNotRaised`; `enabled=false` (если введём kill-switch) → не оценивается
**Then** однозначность: `raised` ⟺ (цена/км и median есть, sample ≥ min, цена/км > median×factor). Property-тест; никаких аномалий «из воздуха».
[Source: prd.md#FR-20:237-238; epics.md:1437-1443; architecture.md:160, 596-598; CLAUDE.md «honesty over inference»]

**AC3 — Детерминированное сравнение цены с порогом (цена/км vs медиана × фактор)**
**Given** деньги — целые ₸ (Q3 Story 4.1), фактор — дробный (1.5)
**When** считается порог `медиана × deviation_factor`
**Then** сравнение ДЕТЕРМИНИРОВАНО и пересчитываемо вручную (тот же вход + та же `methodology_version` → тот же результат бит-в-бит); правило округления/сравнения зафиксировано (см. Q1) — НЕ зависящее от платформенной плавающей точки в граничных случаях.
[Source: architecture.md:298, 557-558, 736 (детерминизм/целые ₸); prd.md#FR-23; data-model §2:78]

**AC4 — Интеграция с risk_flags + порядок (флаги ПОСЛЕ benchmark); живые суммы/длина — дескоуп**
**Given** таблица `risk_flags` + `RiskFlagStore` (Story 4.2) + кэш `price_benchmarks` + `recalc.Run` (Story 4.1)
**When** пересчёт флагов
**Then** флаг price_per_km идемпотентно публикуется/снимается в `risk_flags` (`flag_type='price_per_km'`, как single_participant в 4.2); медиана группы берётся из кэша `price_benchmarks` (пересчитанного ПЕРЕД флагами — порядок `recalc.Run`); подключён как `recalc.FlagRecalculator`; ЖИВЫЕ суммы (`/v2/contract`, Epic 2) и `geo_objects.length_km` (Epic 3) — ДЕСКОУП (на синтетике цена/км из golden-фикстур; реальная цена/км — когда появится длина). Критерий закрытия AC4 = «recalculator подключён + idempotent risk_flags + тест на синтетике + источники задокументированы для Epic 2/3».
[Source: epics.md:1405-1407, 1441-1443; architecture.md:880-881; data-model:49 (geo_objects.length_km), §1; Story 4.1 (price_benchmarks/recalc), 4.2 (risk_flags/RiskFlagStore)]

**AC5 — Пересчитываемость и гардрейлы (несущие)**
**Given** гардрейлы платформы
**When** флаг принимается
**Then** (а) порог — ТОЛЬКО из methodology_params (литералов нет); (б) `methodology_version` в evidence == в params; (в) приёмка на ДАННЫЕ (Go/SQL), не на экран; (г) НЕЙТРАЛЬНОСТЬ (флаг — «сигнал, требующий проверки», через render; нет taboo); (д) честность: insufficient ⟺ нет цены/медианы или sample<min; (е) формула намеренно простая (×1.5, НЕ MAD) — публичная объяснимость.
[Source: prd.md#FR-20, FR-23, §7.1/§7.4; architecture.md:591-592, 596-598, 647; data-model §2:78; epics.md:1594]
