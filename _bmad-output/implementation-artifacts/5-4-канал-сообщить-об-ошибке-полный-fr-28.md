## Story

**Как** гражданин,
**Я хочу** сообщить об ошибке в данных/флаге без аккаунта,
**Чтобы** у факта был досудебный канал возражения.

Контекст: на MVP нет кабинетов и права ответа (этап 5), поэтому FR-28 — **несущее юридическое ограждение** (§7.1,
[NOTE FOR PM] prd.md:315): прямой досудебный инструмент защиты от исков о деловой репутации. Вместе с пересчитываемой
методикой (FR-23, Story 5.3) и опорой только на официальный источник (ows_v2) это главная правовая опора платформы.
[Source: prd.md §5.11 FR-28; epics.md#Epic 5 → Story 5.4; architecture.md:49]

## Acceptance Criteria (дословно из эпика)

### AC-1 — Полная форма с честным автоматом состояний (расширяет дверь-stub 1.9)
**Given** форма «сообщить об ошибке» (расширяет дверь-stub из 1.9)
**When** гражданин отправляет (что не так + контакт по желанию, без аккаунта)
**Then** состояния пусто→заполнение→отправка(защита от двойной)→успех→ошибка; запись падает в Directus-очередь.

Тестируемо:
- Состояния явные и честные: `idle` (пусто) → `filling` → `submitting` (кнопка заблокирована, защита от двойной отправки)
  → `success` (подтверждение, форма закрыта/сброшена) → `error` (честное «не удалось отправить, попробуйте ещё раз»,
  введённый текст НЕ теряется).
- Поля: «что не так» (обязательно, textarea), «контакт по желанию» (опционально), привязка к объекту (авто из контекста:
  `contract_id` и/или `flag_id` и/или вид объекта — НЕ вводится руками).
- Без аккаунта/логина. Запись POST'ится на новый бэкенд-эндпоинт → строка в таблице `error_reports` (Directus-очередь).
- Нейтральность (§7.1): тексты формы — «сообщить об ошибке в данных», ноль табу-лексики (kk+ru, парность).

### AC-2 — Достижимость рядом с каждым флагом + deep-link из Telegram (UX-DR28)
**Given** достижимость (UX-DR28)
**When** флаг доходит до третьих лиц
**Then** форма достижима рядом с КАЖДЫМ флагом + deep-link из Telegram-пуша.

Тестируемо:
- Дверь «Сообщить об ошибке» открывает форму (а не только mailto) рядом с каждым флагом: бейдж (`FlagBadge`, gate-проп
  `reportErrorHref`/коллбэк), экран методики (`MethodologyDialog`), подвал карточки (`ReportError`). Gate нейтральности
  1.9 (флаг без двери НЕ публикуется) сохраняется.
- Deep-link: существует маршрут/параметр, позволяющий открыть форму сразу для конкретного объекта (контракт/флаг) по
  ссылке. ⚠️ Сам Telegram-пуш, который шлёт ссылку, — Epic 7 (бота ещё нет); 5.4 строит ЦЕЛЬ deep-link, не отправителя.

### AC-3 — Расширение «точка не там» (AR-28) → wrong_reported (питает SM-C2)
**Given** расширение «точка не там» (AR-28)
**When** сообщена ошибочная геопривязка
**Then** фиксируется как `wrong_reported` (питает SM-C2).

Тестируемо:
- Форма поддерживает вид обращения «неверная геопривязка» (`kind = geo_wrong_point`) с привязкой к гео-объекту/лоту.
- ⚠️ Полная простановка `wrong_reported` на `geo_objects` + счётчик SM-C2 на `/metrics` — **Epic 3** (геокуратор
  `geo_objects` verified/wrong_reported ещё не построен; сейчас карта = `interim_geo_lots`, Story 0.8). 5.4 ФИКСИРУЕТ
  обращение (строка `error_reports.kind=geo_wrong_point`); связывание с `geo_objects.wrong_reported` и инкремент SM-C2 —
  honest boundary к Epic 3. См. Open Questions.

   `id`, `kind` (CHECK: `data_error|flag_error|geo_wrong_point`), `subject_type` (CHECK: `contract|contractor|geo_object`),

   `status`/`created_at`. **goose Down** дропает.
2. **Бэкенд: `POST /api/error-reports`** (ПЕРВЫЙ write-эндпоинт). Декод JSON-тела (лимит размера тела —
   `http.MaxBytesReader`), валидация (message непуст и в разумном лимите длины; kind/subject_type из enum;
   contact опционален), запись строки через sqlc-запрос (`InsertErrorReport`), ответ `201` с честным телом
   (id/принято) или `400` (валидация) через `apierr`. Нейтральная серверная доктрина (без табу). НЕ требует токена.
3. **OpenAPI + codegen:** новый путь `POST /api/error-reports` + схемы `ErrorReportRequest`/`ErrorReportResponse`

4. **sqlc-запрос** `error_reports.sql` (`InsertErrorReport`) → `make gen-sqlc` (per-file .gen.go, анти-churn).
5. **Фронтенд-форма** `ReportErrorForm` (расширяет `ReportError`): честный автомат состояний (AC-1), поля, защита от
   двойной отправки (disable-on-submit), POST через клиент (`postErrorReport` в `reportError.ts` или `useReportError`

6. **Достижимость (AC-2):** переключить gate-точки (бейдж/методика/подвал) на открытие формы для конкретного объекта;
   deep-link-маршрут/параметр (цель для Epic 7). Сохранить gate нейтральности (дверь обязательна у флага).
7. **«Точка не там» (AC-3):** форма умеет `kind=geo_wrong_point` с привязкой к лоту/гео-объекту; строка `error_reports`

8. **i18n** новые `report_error.form.*` (kk+ru, парность) — нейтральные.
9. **Гранты БД (Directus-очередь):** `error_reports` — API имеет INSERT (+ чтение своей вставки), Directus —
