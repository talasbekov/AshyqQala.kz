## Story

**Как** гражданин,
**Я хочу** полную проверяемую карточку контракта,
**Чтобы** я понимал, кто отвечает, и мог проверить первоисточник.

Контекст: это «полная» версия сквозной карточки 1-7. Она **замещает ручные `evidence` среза 1-9 реальным compute Эпика 4** и впервые подаёт на карточку настоящие `risk_flags` (с `evidence` + `methodology_version`) под gate нейтральности. Карточка-скелет, URL-схема и постоянный id берутся из Эпика 1; расчётные read-модели — из Эпика 4.

## Acceptance Criteria

Первые три критерия — **дословно из эпика** (контракт истории). AC-4…AC-8 — производные, тестируемые уточнения, вытекающие из фактического состояния кода и ретро Эпика 4.

### AC-1 — Данные контракта (FR-10)
**Given** карточка контракта (поверх read-моделей Epic 4)
**When** она открыта
**Then** показаны сумма/предмет/Заказчик/Подрядчик/сроки/статус; отсутствующее поле → «нет данных» `{data-state-nodata}`, **не «0»**; «Подрядчик»/«Район» — кликабельные ссылки.

Тестируемо:
- Все поля проходят через honesty-обёртку `Value` (`state==='ok' && value!==null` → значение, иначе `<DataState>`); регрессия `ok+null` (правленая P1 в 1-7) не воспроизводится.
- `amount_tng` приходит на провод **строкой** (bigint > 2^53), форматируется через `Intl.NumberFormat` (`formatMoney`), никогда не конкатенацией.
- «Подрядчик» и «Район» — единственные кликабельные `<dd><a>` метаданных; «Заказчик» и «Тәсіл/способ» — обычный текст. Если у контракта нет привязки к `organizations` (см. границу токена) — поле честно показывает `{data-state-nodata}`, а ссылка не рендерится (не ведёт в никуда).
[Source: prd.md#5.4 FR-10; epics.md#UX-DR7; architecture.md#Format-Patterns (money/null); EXPERIENCE.md#Component-Patterns]

### AC-2 — Первоисточник и акт (FR-11)
**Given** первоисточник и акт (FR-11)
**When** карточка отрисована
**Then** рабочая `{source-link}` «Первоисточник: goszakup.gov.kz ↗» (kk: «Бастапқы дереккөз: goszakup.gov.kz ↗»); при акте (`/v2/acts`) — дата и подписант (ФИО/должность как **служебная информация** должностного лица).

Тестируемо:
- `{source-link}`: цвет `{link-on-sunken}` (AA на `surface` и `surface-sunken` обоих тем — НЕ `{link}`, который 4.28:1 на sunken), всегда подчёркнута (`underline-offset:2px`), `rel="noopener"`, новая вкладка. **`source_url` уже отдаётся API и рисуется** на карточке (часть FR-11 готова с 1-7) — проверить регресс, не переписывать.
- Акт — **новый сквозной путь**: миграция `acts` (нет в `migrations/`, стоп на 0009) → sqlc-запрос → поле DTO/OpenAPI → блок на карточке. Показывает `act_date` и `signer_info` (служебная инфо по §6.2.4, нейтрально, не приватные данные). При отсутствии акта — честное состояние, **не пустота и не выдумка**.
- Данные акта на синтетике сидируются сейчас (1–2 демо-акта); реальные — после токена (`/v2/acts` токен-зависим).
[Source: prd.md#5.4 FR-11; data_model#1.C `acts(act_date, signer_info, source_url, contract_id, goszakup_act_id)`; review-accessibility.md (link-on-sunken AA); architecture.md#Format-Patterns]

### AC-3 — Активные флаги под gate нейтральности (FR-12, FR-23)
**Given** активные флаги (FR-12) и gate нейтральности
**When** флаг публикуется на карточке
**Then** показан нейтрально «… — сигнал, требующий проверки» с глифом «!», ведёт к методике (5.3); **БЕЗ пути к методике и каналу «Сообщить об ошибке» флаг НЕ публикуется**.

Тестируемо:
- Флаги приходят из **реального compute Эпика 4** (`risk_flags` + `evidence` + `methodology_version`), а **не** из захардкоженного `contractStories.ts` (текущий источник — `STORIES[DEMO-...]`). Это и есть центральная интеграция 5-1.
- Текст бейджа — только нейтральный фрейм «… — сигнал, требующий проверки» / «… — тексеруді талап ететін сигнал»; глиф «!» (не-цветовой признак, паритет с map-marker); амбер-фон; **никогда не алый**.
- Gate структурно зашит: `FlagBadge` имеет **обязательные** props `onOpenMethodology` И `reportErrorHref` — флаг не компилируется/не рендерится без пути к методике и каналу возражения (AR-14, UX-DR28). API-driven флаги обязаны сохранить этот gate.
- Тап по бейджу → методика (экран 5-3, downstream); рядом с **каждым** флагом — «Сообщить об ошибке» (не только в футере).
[Source: prd.md#5.4 FR-12, #5.8 FR-23; epics.md#AR-14, UX-DR8, UX-DR28; EXPERIENCE.md «Правило достижимости защитных связей»]

### AC-4 — Реконструкция честных состояний на чтении (наследие Epic 4 → 5) 🔑
**Given** стор хранит только `raised`-строки (`risk_flags`; `not_raised`/`insufficient_data`/`not_published` = «нет строки»)
**When** карточка читает флаги
**Then** читающий слой **выводит `flag_state` из доступности evidence/входов**, а не из факта строки; карточка **никогда молча не подразумевает «всё чисто»**.

Тестируемо:
- Контейнерное состояние показывается явной строкой: «нет активных сигналов по этому контракту» ≠ молчание/пустой блок (`container_state: no_flags_raised`).
- Property-тест: нельзя показать «сигнала нет», если evidence/входы для расчёта недоступны → должно быть `insufficient_data` («недостаточно сопоставимых данных» — рендерится только при `comparable_n < min_sample`, тем же порогом, что в evidence).
- Четыре состояния `flag_state` (`raised`/`not_raised`/`insufficient_data`/`not_published`) различимы на чтении.
[Source: epic-4-retro-2026-06-25.md (директива повторена 3×); deferred-work.md «store схлопывает честные состояния → реконструировать на чтении (Epic 5)»; architecture.md#Format-Patterns flag_state]

**When** карточка контракта рендерит флаги

- Ноль табу-лексики в **обоих** языках на всех строках карточки (RU: «нарушение/коррупция/виновен/преступник/вор/нарушитель/разоблачаем/схема»; KZ: «бұзушылық/сыбайлас жемқорлық/кінәлі/қылмыскер/ұры/әшкерелейміз»); «недобросовестный/жосықсыз» — только как цитата названия реестра РНУ.

- Пустые данные никогда не маскируются «0 ₸»/«—»/«н/д».
