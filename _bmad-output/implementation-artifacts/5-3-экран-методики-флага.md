## Story

**Как** Данияр-журналист,
**Я хочу** видеть, как построен флаг, и пересчитать его,
**Чтобы** я проверял аномалию перед публикацией.

Контекст: экран методики — несущая инженерная и юридическая гарантия проекта (NFR-5: «каждый Флаг пересчитываем с версией методики»). Реализует **FR-23** (пересчитываемость, публичная методика). 5-1 ведёт сюда тап по бейджу; 5-3 делает экран полным и пересчитываемым третьим лицом. Формула намеренно простая (×1.5, не MAD) — чтобы журналист пересчитал вручную.
[Source: epics.md#Epic 5 → Story 5.3; prd.md#5.8 FR-23, #6 NFR-5]

## Acceptance Criteria (дословно из эпика)

### AC-1 — Полный экран методики при выставленном сигнале
**Given** тап по `{flag-badge}` на любой поверхности
**When** открыт экран методики
**Then** показаны формула (×1.5), пороги, ключ сопоставимости, `evidence`, `methodology_version`, дата расчёта, кнопка «пересчитать вручную».

Тестируемо:
- Формула из `methodology_params` плейсхолдером (НЕ литерал в прозе): «цена за км > медиана × {factor}», factor из evidence/params (1.5). Числовых литералов-порогов в шаблонах нет (registry-линтер).
- Пороги показаны ВСЕГДА: `min_sample` (5), окно 24 мес, `deviation_factor` (1.5) — для price_per_km; для монополии — `concentration_share` (0.5), `min_group_contracts` (5).
- Ключ сопоставимости человекочитаемо: направление × район (КАТО) × окно 24 мес.
- `evidence` (все входы расчёта), `methodology_version` (v1.0), дата расчёта (`detected_at`) — из API (5-1 уже отдаёт `methodology_version`/`detected_at`/`evidence` в `ContractFlagDTO`).
- «Пересчитать вручную» — рабочий воркшит (см. AC-3), не просто заметка.

### AC-2 — Методика при НЕ выставленном сигнале (формула всегда, какого порога не хватило)
**Given** сигнал не выставлен
**When** методика открыта
**Then** формула и пороги показываются ВСЕГДА; вместо значения — «недостаточно сопоставимых данных» с указанием, **какого порога не хватило** (`min_sample` / `min_group_contracts`, **разделены**).

Тестируемо:
- При `insufficient_data` формула/пороги видны; медиана/значение не показаны (честность: не выдумываем).
- Различать ПОРОГ по флагу: price_per_km → не хватило `min_sample` (выборка < 5); монополия → не хватило `min_group_contracts` (контрактов в группе < 5). Не сваливать в один обобщённый текст.
- Текст «Отсутствие сигнала — не "всё чисто", а недостаток данных для сравнения» (i18n `methodology.insufficient_note`, уже есть).
- ⚠️ Граница (наследие 5-1): read-side различает `insufficient_data` по ОТСУТСТВИЮ строки → конкретный sample/min недоступны на чтении для «нет строки»-случая (стор схлопывает, Epic 4 follow-up). 5-3 показывает пороги ВСЕГДА из params; конкретную выборку — когда evidence её несёт. См. Dev Notes.

### AC-3 — Воркшит ручного пересчёта
**Given** воркшит-пересчёт
**When** журналист подставляет числа
**Then** человекочитаемый рендер `evidence` + явный критерий «похожести» + `as_of`/snapshot-id.

Тестируемо:
- Человекочитаемый рендер evidence: каждое поле — подпись + значение (суммы через `formatMoney`, даты через `formatDate`, БИН моно-шрифт).
- Явный критерий «похожести»: «сопоставимы контракты того же направления и района (КАТО) за последние 24 мес; выборка ≥ 5».
- `as_of`/snapshot-id: показать `methodology_version` (v1.0) + дату расчёта как «срез на дату». ⚠️ Полный `snapshot_id` + перманентная ссылка-на-дату (AR-29) — **Story 5.6** (evidence сейчас несёт `methodology_version`, не `snapshot_id`). 5-3 даёт version+date как срез; permalink — 5.6.
