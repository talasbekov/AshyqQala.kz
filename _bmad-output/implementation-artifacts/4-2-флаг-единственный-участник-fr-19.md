# Story 4.2: Флаг «единственный участник» (FR-19)

## Story

As a **система AshyqQala.kz (compute-ядро)**,
I want **помечать контракт нейтральным флагом «единственный участник», когда в объявлении зафиксирован 1 участник и способ закупки НЕ в списке законных исключений — по пересчитываемой методике (`methodology_params`), с полным `evidence`**,
so that **гражданин/журналист видит сигнал, требующий проверки (UJ-1), а пустые/неполные данные честно дают «недостаточно данных», а не ложный «всё чисто»**.

> **Тип истории:** флаг-история Эпика 4 (compute, **backend-only**). Реализует FR-19 поверх движка/состояний Эпика 1 + methodology-конфига Story 4.1. **Гардрейл эпика:** выход НЕ виден пользователю и НЕ «опубликованный флаг» — приёмка на ДАННЫЕ (Go/SQL-ассерт), не на экран. [Source: epics.md:1383, 1594; prd.md#FR-19]
>
> **⚠️ Sprint Change (2026-06-24, решение владельца):** Epic 4 формально помечен «🚫 ожидает токен» (`epics.md:1385`: участники для FR-19 даёт `/v2/trd-buy` = живой ows_v2). Владелец 2026-06-24 расширил **прецедент Story 4.1** (токен-независимый compute на синтетике + честный дескоуп живых данных) на флаги: 4.2 строит ЧИСТУЮ логику флага + `risk_flags` + порог `single_participant.exclude_methods` + evidence НА СИНТЕТИКЕ; живую привязку к `/v2/trd-buy` (проекции `announcements`/`participants`) ДЕСКОУПИТ на Epic 2 (как 4.1 десакоупила live-recalc на 2.4). НЕ ждать токен; НЕ выдумывать данные участников (нет данных → `insufficient_data`).

## Acceptance Criteria

**AC1 — Чистый флаг single-participant: `(inputs, params) → (FlagState, evidence)`; пороги ТОЛЬКО из methodology_params**
**Given** ЧИСТЫЙ пакет `internal/flags` (наполняет каркас Story 1.10) + `methodology_params.flag.single_participant.{enabled, exclude_methods}` (загружается через `internal/methodology`, Story 4.1) + входы флага: число участников объявления (`*int`, nil = нет данных) и способ закупки (string)
**When** `enabled == true` И число участников `== 1` И способ закупки ∉ `exclude_methods`
**Then** возвращается `registry.FlagRaised`; `evidence` (структура, НЕ строка) хранит ВСЕ входы: `participant_count`, `procurement_method`, `exclude_methods`, `enabled`, `methodology_version`; числовые/списковые пороги берутся ТОЛЬКО из `methodology_params` (литералов в коде/прозе нет); пакет `flags` остаётся ЧИСТЫМ (страж `internal/arch` зелёный: нет импортов `store`/`httpapi`/`goszakup`/`time`/pgx/chi).
[Source: prd.md#FR-19:230; data-model §2:74-75; architecture.md:160, 591-592, 596-598, 775-776; epics.md:1417-1419]

**AC2 — Честные состояния + авто-снятие (FR-19 «флаг снимается автоматически»)**
**Given** идемпотентный пересчёт флага
**When** условие перестало выполняться
**Then** однозначно: участников `> 1` ИЛИ способ ∈ `exclude_methods` → `FlagNotRaised` (флаг снят, не «raised»); число участников отсутствует (`nil`) → `FlagInsufficientData` (флаг БЕЗ данных НЕ строится — НЕ ложный `not_raised`); `enabled == false` → флаг не оценивается; границы (участников `0`/отрицательное — невозможная синтетика) → честно, без паники. Property-тест однозначности: нельзя `raised` без `count==1 && method∉exclude`.
[Source: prd.md#FR-19:231; epics.md:1421-1423; architecture.md:596-598; CLAUDE.md «honesty over inference»]

**AC3 — `risk_flags` как производное: идемпотентный пересчёт + evidence/methodology_version персистятся**
**Given** таблица `risk_flags` (`flag_type`, `subject_type`, `contract_id`/`organization_id`, `severity`, `evidence` jsonb, `is_active`, `detected_at`, `cleared_at`, `methodology_version`) — производное от чистой функции (одна истина)
**When** запускается пересчёт флагов
**Then** запись/снятие ИДЕМПОТЕНТНЫ (повтор не плодит дублей — UPSERT по `(flag_type, contract_id)`; снятие ставит `is_active=false` + `cleared_at`, НЕ удаляет историю); `evidence` + `methodology_version` персистятся (пересчитываемость третьим лицом); детерминизм (тот же вход + та же `methodology_version` → тот же результат).
[Source: data-model §E:54; architecture.md:122, 431, 591; prd.md#FR-23]

**AC4 — Порядок: флаги ПОСЛЕ benchmark (оркестратор 4.1); живой источник участников — Epic 2 (дескоуп)**
**Given** оркестратор `recalc.Run` (Story 4.1, порядок benchmark→flags) и `recalc.FlagRecalculator` (интерфейс)
**When** пересчёт
**Then** single-participant recompute подключается как реализация `FlagRecalculator` (флаг считается ПОСЛЕ benchmark swap); ЖИВАЯ привязка к `/v2/trd-buy` + проекции `announcements`/`participants` ДЕСКОУПЛЕНА на Epic 2 (честно, без выдуманного источника) — 4.2 поставляет чистый флаг + idempotent `risk_flags` + пересчёт на СИНТЕТИЧЕСКИХ участниках + тест; критерий закрытия AC4 = «flag-recalculator подключён к recalc.Run + тест + источник участников задокументирован для Epic 2».
