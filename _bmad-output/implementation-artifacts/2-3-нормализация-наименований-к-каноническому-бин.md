## Dev Notes

### Контекст истории (зачем и где границы)

Story 2.3 реализует **FR-2** (нормализация вариативных написаний Организаций к одному каноническому БИН: однозначные — авто; неоднозначные — очередь оператору; конфликт БИН↔наименование — изоляция). Цель — «один подрядчик = один профиль», чтобы агрегаты/флаги (монополия FR-21, агрегаты подрядчика FR-13) считались по чистым сущностям, а не размазывались по вариантам написания.

**Почему токен-независимо (разведка 2026-06-27):** (1) логика нормализации — чистый домен над записями организаций, без вызовов ows; (2) вход (БИН+наименования) доступен через `FileSource.Fetch` из `contract`/`trd-buy` дампов; (3) каркас стоит — `internal/normalize` стаб из 1.10 ждёт наполнения, `store/curation` даёт механику кураторской очереди. Прецедент — **Story 2.0** (вырезала `lots`+`Source` из токен-гейченной 2.1); 2.3 несёт аналогичную вырезку: фундамент `organizations`+`org_name_aliases`+лексикон + движок, на фикстурах.
