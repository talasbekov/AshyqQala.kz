## Story

**Как** гражданин,
**Я хочу** историю и репутацию подрядчика,
**Чтобы** я оценивал исполнителя по проверяемым фактам.

Контекст: карточка подрядчика — вторая половина «полной проверяемой картины» Эпика 5 (после карточки контракта 5-1). Сюда уходят **contractor-субъектные** сигналы, которые 5-1 честно оставила вне карточки контракта: **монополия (FR-21)** и **РНУ (FR-22)**. Карточка контракта (5-1) ссылается на подрядчика — здесь эта ссылка получает целевую страницу.

## Acceptance Criteria (дословно из эпика)

### AC-1 — Агрегаты по каноническому БИН (FR-13)
**Given** агрегаты по каноническому БИН (FR-13)
**When** карточка строится
**Then** БИН, список Контрактов, суммы, регионы (КАТО), агрегированные флаги; строится при неполном профиле («профиль неполный»); при `manual`/`conflict` — «профиль уточняется», флаги не используются как основание.

Тестируемо (Consequences FR-13):
- Карточка строится даже при неполном профиле (помечается «профиль неполный»).
- Агрегаты считаются по каноническим Организациям (**после нормализации FR-2** — Epic 2).
- При `resolve_status ∈ {manual, conflict}` — «профиль уточняется», флаги НЕ основание для выводов (нейтральность + честность над домыслом).

### AC-2 — Метка РНУ (FR-14)
**Given** метка РНУ (FR-14)
**When** БИН в `/v2/rnu`
**Then** показана метка со ссылкой на реестр и датой; авто-снятие по `end_date`; «недобросовестный» — **только** как цитата названия реестра.

Тестируемо (Consequences FR-14):
- При активной записи РНУ — метка со ссылкой на реестр + дата.
- Метка снимается автоматически при выходе БИН из реестра (по `end_date`).
- Лексика: «недобросовестный/жосықсыз» допустимо ТОЛЬКО как цитата названия гос-реестра с атрибуцией государству (таб у-исключение, review-neutrality).

### AC-3 — Достижимость защитных связей на КАЖДОЙ репутационной метке
**Given** каждая репутационная метка
**When** она отрисована
**Then** у неё СВОЯ `{source-link}` и **ЛОКАЛЬНАЯ** ссылка «Сообщить об ошибке» (не одна общая на карточку).
[Source: epics.md#Epic 5 → Story 5.2; AR-14/UX-DR28 gate нейтральности — на КАЖДУЮ метку]

## Dev Notes (для момента разморозки)

### Что 5-2 построит (когда фундамент появится)
- **Backend:** новый endpoint `GET /api/contractors/{bin}` (или `/{organization_id}`) → DTO с БИН, name (lang-конверт), агрегатами (count контрактов, сумма ₸ строкой, регионы КАТО), агрегированными флагами (monopoly/rnu — честная реконструкция на чтении как в 5-1, `resolveContractorFlags` по аналогии с `resolveContractFlags`), меткой РНУ (из `rnu_entries`, дата + source_url), профилем (`resolve_status` → «полный»/«неполный»/«уточняется»). sqlc-запросы: список контрактов по `supplier_org_id`, агрегаты SUM/COUNT/regions, РНУ по org. OpenAPI + regen.
- **Frontend:** новая фича `web/src/features/contractor/` (ContractorCard.tsx + useContractor.ts + route) — НЕ существует. Карточка контракта 5-1 (`Подрядчик`-поле) получит живую ссылку сюда (закрывает defer 5-1).
- **Honest-реконструкция (наследие, как в 5-1):** агрегированные флаги — нет строки → insufficient, никогда молчаливое «чисто»; при `manual/conflict` профиле — флаги НЕ основание (показывать «профиль уточняется»), это усиление честности над домыслом.

### Ключевые уроки из 5-1 (применить дословно)
1. **Честная реконструкция состояний на чтении** — обязательна и для агрегированных флагов подрядчика (`resolveContractorFlags`-аналог).
2. **Стражи обязаны доказать, что краснеют** ([[guards-must-prove-red]]) — negative-control + `-count=1` + пин литералом; не тавтологичные тесты порядка.
3. **Gate на КАЖДУЮ метку** (AC-3) — структурно через обязательные props (как `FlagBadge`); локальная «Сообщить об ошибке» + своя `{source-link}` у каждой метки, не одна общая.
4. **Деньги строкой** (агрегатные суммы — bigint → строка); **числа evidence** — каноничные строки для `formatMoney` (адаптер); защита от чисел > 2^53.
5. **Нейтральность РНУ:** «недобросовестный» — только цитата названия реестра (review-neutrality critical-фикс); per-surface нейтральность-тест в обеих локалях.
6. **anti-churn sqlc** (`make gen-sqlc`, не править `gen/*`); коммит на историю.
