# AshyqQala.kz — Runbook аудита данных (Этап 0) v1

> Исполняемая процедура аудита данных перед стартом спринта MVP. Цель — подтвердить, что данные goszakup автоматизируемы, и снять главный риск сроков (автогеопривязка ≥70%). Закрывает открытые вопросы PRD: **OQ-1** (число контрактов), **OQ-4** (Go/No-Go геопривязки), **OQ-6** (достаточность данных для флагов/медиан). Источник критериев: конкурсный документ §2 (этап 0), §3.4–3.5, §4.3.
>
> `[ASSUMPTION]` Точные имена полей/эндпоинтов ows_v2 уточняются по факту доступа к API; ниже — логический уровень и проверяемые метрики.

## 0. Результат аудита (что должно быть на выходе)

Заполненная таблица решения (§6) + короткая записка с числами. Аудит даёт **Go / No-Go / Go-с-фолбэком** для спринта MVP.

## 1. Предусловия

- [ ] **Токен ows_v2 получен** (профиль участника на goszakup.gov.kz). _Риск: задержка выпуска токена — заложить буфер._
- [ ] Доступ к `/v2/journal`, договорам, лотам, объявлениям (`/v2/trd-buy`), участникам, `/v2/rnu`, `/v2/acts` проверен (200 OK на тестовый запрос).
- [ ] Список КАТО районов Астаны зафиксирован (Алматы, Сарыарка, Есиль, Байконыр, Нура).
- [ ] Определён фильтр «дороги» и «водоснабжение» (по предмету/коду закупки) — `[ASSUMPTION]` уточнить классификатор на выборке.

## 2. Шаг A — Объём и полнота данных *(закрывает OQ-1)*

**Что делаем:** выгрузить договоры Астаны по направлениям «дороги» + «вода» за последние 24 мес.

**Мерим:**
| Метрика | Как считать | Порог/цель |
|---|---|---|
| Число контрактов | count договоров (дороги+вода, КАТО Астаны, 24 мес) | зафиксировать факт → обновить NFR-2 и TAM премиума (§5.3) |
| Полнота суммы | доля записей с непустой суммой | `[ASSUMPTION]` ≥ 95% |
| Полнота БИН подрядчика/заказчика | доля с валидным БИН | ≥ 98% |
| Полнота сроков | доля с план. датами | ≥ 80% |
| Наличие акта (`/v2/acts`) | доля контрактов со связанным актом | зафиксировать (влияет на NFR-8) |
| Ссылка на первоисточник | формируется для 100% | 100% |

**Стоп-сигнал:** полнота суммы/БИН ниже порога → +3–4 нед. на слой очистки (риск §2).

## 3. Шаг B — Автогеопривязка *(закрывает OQ-4 — ГЛАВНЫЙ гейт)*

**Что делаем:** на выборке (≥200 контрактов или 100%, если меньше) прогнать черновой автогеокодер по адресу/КАТО.

**Мерим:**
| Метрика | Как считать | Порог |
|---|---|---|
| **Автопокрытие** | доля объектов, получивших точку автоматически с приемлемой уверенностью | **≥ 70% → Go; < 70% → фолбэк** |
| Доля распознаваемых адресов | есть структурированный адрес/ориентир | вход для оценки покрытия |
| Дороги как полилинии | доля дорожных объектов с возможностью задать `length_km` | влияет на флаг цены/км (FR-20) |

**Решение по гейту (FR-6):**
- **≥ 70%** → уличная карта (FR-7) в полном объёме.
- **< 70%** → **фолбэк-режим**: карта на уровне Районов + поиск (FR-9); уличная карта добивается ручной разметкой через Directus (FR-5) по мере сил.

> Это та самая контрольная точка «неделя 3 спринта» из §3.4 — но предварительную оценку лучше получить ещё на этапе 0.

## 4. Шаг C — Нормализация наименований

**Что делаем:** оценить вариативность написаний Организаций.

**Мерим:**
| Метрика | Порог |
|---|---|
| Доля однозначно сводимых к БИН автоматически | `[ASSUMPTION]` ≥ 90% |
| Доля неоднозначных (в очередь оператору, FR-2) | оценить объём ручной работы |
| Конфликты «БИН ↔ наименование» | зафиксировать число (изоляция, FR-2) |

**Стоп-сигнал:** высокая доля неоднозначных → недооценка нормализации (риск §2) → расширить буфер.

## 5. Шаг D — Достаточность данных для флагов и медиан *(закрывает OQ-6)*

**Что делаем:** проверить, хватает ли данных для 4 флагов (FR-19…FR-22) и медиан (FR-18).

**Мерим:**
| Проверка | Критерий |
|---|---|
| Флаг «единственный участник» (FR-19) | в `/v2/trd-buy` доступно число участников по объявлению |
| Медиана ₸/км (FR-18/FR-20) | в группах (направление × КАТО × 24 мес) выборка ≥ `median.min_sample` (5) хотя бы для части групп; иначе массово «недостаточно данных» |
| Монополия (FR-21) | достаточно контрактов в группе (КАТО × направление) ≥ `min_group_contracts` (5) |
| РНУ (FR-22) | `/v2/rnu` отдаёт `start_date`/`end_date` по БИН |

**Результат:** подтвердить/скорректировать стартовые дефолты `methodology_params` на реальных распределениях (закрывает OQ-6).
